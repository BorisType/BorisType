# Skill веб-администратора: первый сценарий

Дата: 2026-11-10. Пользователь согласовал отдельный `websoft-hcm-admin`
в текущем каталоге skills с постепенным пополнением проверенных маршрутов UI.

## Граница шага

- Короткий entrypoint и один reference по сотрудникам, без зависимости от MCP.
- Вход через `/admin`, каталог **Персонал → Сотрудники**, двойной щелчок,
  общие и контактные поля, снимки с учётом открыто отображаемого пароля.
- Пояснение пользователя о переиндексации по расписанию и обычных фильтрах
  отдельно от браузерного evidence. 20 минут — пример, не общий контракт.
- Создание через XML API и чтение в браузере проверены; UI-сохранение пока нет.
- Discovery, выборочная установка, самодостаточность references и применение
  на вопросе о свежей записи без результатов полнотекстового поиска.

## Evidence

В браузере на Linux HCM 2025.2.1333 / .NET 9.0.11 / PostgreSQL 16 / legacy model
открыта существующая собственная тестовая запись. Подтверждены переход `/admin`
на `/spxml_web/main.htm`, подписи каталога, открытие двойным щелчком и поля
разделов **Общие сведения** / **Анкетные данные**. В исходной проверке поиск
по фамилии/ФИО дал пустую выдачу; очистка строки с Enter вернула каталог,
в котором запись была видна. Пользователь объяснил это периодичностью
полнотекстовой индексации. Расписание, ожидание переиндексации и настройка
обычного фильтра отдельным воспроизводимым сценарием пока не подтверждены.

Персональные данные тестовой записи, пароль, ID, адрес стенда и исходные
снимки остаются вне git. Запись сохранена для пользователя; этот шаг её
не изменяет и не удаляет. Работающий стенд и подключение MCP сохраняются.

## Проверка полезности

Baseline `/root/admin_skill_baseline` получил сценарий: созданная через API
запись не находится по фамилии; нужно открыть её в админке, сверить поля
и сделать снимки без создания дублей. Новый skill и история исследования
ему недоступны. Ответ осторожный, не выдумывает UI и правильно различает
API-запись и UI-сохранение, но не содержит маршрута `/admin`, названий разделов,
двойного щелчка и знания о расписании индекса. Например: «Неизвестны …
расположение полей в карточке»; «Для открытия карточки использую реально
обнаруженную ссылку или механизм открытия записи в этой версии админки».
Открытое отображение пароля при подготовке снимков также не учтено.
Это пробел reference, а не нарушение дисциплины.

`/root/admin_skill_check` получил тот же сценарий и только установленную
копию нового skill вне checkout, без браузера и исходного исследования.
Ответ применил `/admin`, нужный каталог, очистку поиска с Enter,
двойной щелчок, разделы и точные подписи полей. Учтены открытый пароль,
различие API/UI-сохранения, отсутствие гарантии «ровно через 20 минут»
и непроверенная последовательность обычного фильтра. Новых утверждений
о проверенном UI-сохранении или универсальности маршрута не появилось.
Это один baseline и один application check, не статистическая оценка модели.
