# Миграция документации: причины, решения и учёт

Дата: 2026-11-11. Работа ведётся в [PR #59](https://github.com/BorisType/BorisType/pull/59)
от baseline `8ff2739ce14957e9f1d3e3b17c7a7cf88a396209`.
Содержательная миграция завершена в рамках этого PR. Это запись изменения базы знаний; постоянные правила находятся в
[development](../../development.md), актуальные входы — в [refs](../../README.md).

## Почему потребовался переход

BorisType развивался от TS → BS compiler к MCP и самостоятельным C# библиотекам,
а корневое описание, сайт и инструкции оставались преимущественно compiler-centric.
Разделение внешней и внутренней документации существовало с февраля 2026 года,
но знания разошлись по архитектурным снимкам, поколениям AI review и цепочкам
`spec → plan → tasks → results`. В них смешивались выполненное, желаемое и
предполагаемое. У .NET расходились публичные alpha.3/API 1 и реализованные alpha.4/API 2.

Четыре пары Copilot/Cursor инструкций имели одинаковое содержание, отличаясь
whitespace. В них обнаружились устаревшие команды, ложная универсальность env/descriptor
pattern и обязательная церемония JSDoc/ADR/ROADMAP на изменения любого размера.
TODO был указателем на ROADMAP; тот одновременно содержал направления, завершённые
работы, неподтверждённые дефекты и обещания версий с прошедшими датами.

Первый коммит PR ввёл структуру и сохранил старый корпус целиком. Пользователь
попросил завершить содержательную миграцию в том же PR: извлечь полезные знания,
разобрать старые findings и удалить дубли после сверки. Архив не должен становиться
единственным способом восстановить действующий контракт.

## Принятая организация и причины

| Материал                                                                | Место и смысл                                                                                     |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Установка, пользовательские сценарии, параметры и публичные ограничения | `docs/`: сайт; прежние guides/reference маршруты сохранены                                        |
| Быстрый вход в отдельный пакет                                          | README пакета, с полезными ссылками вне checkout                                                  |
| Почему выбран подход, неудачные альтернативы, основания и границы       | Тематические `refs/compiler`, `refs/cli`, `refs/mcp`, `refs/dotnet`, `refs/platform`              |
| Значимое датированное решение                                           | `refs/decisions`; текущий статус и оговорки находятся рядом с исходной записью                    |
| Первичные данные, воспроизведение, конкретный результат                 | `refs/research`, вместе с source/manifests/transcripts/verifiers                                  |
| Конкретный долг                                                         | TODO либо связанный issue; статус не дублируется в нескольких списках                             |
| Крупные направления                                                     | Короткий ROADMAP без ложных дат и номеров версий                                                  |
| Повторяемый workflow агента                                             | Узкий skill: переносимые пользовательские skills в `skills/`, compiler procedure требует checkout |

Имя **`refs/`** выбрано пользователем. Внутренние сведения организованы по вопросу,
а не по номеру сессии. Не требуется читать всю базу, вести ADR на опечатку или
воспроизводить четырёхступенчатую цепочку документов для каждой фичи.

Git сохраняет точный diff, PR — смысловую дельту. Значимое изменение знания или
решения также отражается в тематической базе со старым основанием и новыми данными.
Это позволяет понять причину из checkout, не разыскивая разговор или закрытый PR.

## Что было извлечено и что удалено

[Машинная карта](../../migration-map.json) связывает каждый материал исходного
`ref/` и `plans/`, удалённые editor instructions и переписанные корневые входы
с окончательным местом знания. Исходный SHA256 вычислен по git blob baseline;
`destination` означает место сохранённых сведений, а не обещание текстовой копии.
`sourceRetained` указывает на файл, оставшийся на исходном пути после переписывания.

Промежуточные планы, пустые status wrappers, повторяющиеся ревью и snapshots
старых пользовательских входов удалены после извлечения существенного содержания.
Полные старые bytes остаются в указанной baseline revision. Датированные native
результаты и статические source audits сохраняются, когда сами служат основанием.

Старые wishlist-вехи не превращаются в обязательства. Для registry, REPL, JIT,
LLVM/WASM backend, HMR, coverage-процентов и обещанных релизов не было принятого
дизайна и подтверждённой задачи потребителя; такие обещания сняты. Содержательные
compiler proposals сохраняют отдельно текущий статус и условия возвращения.
Подтверждённые дефекты, опасные обходы и ограничения не закрываются из-за удаления
старого файла: их статус и источник отражаются в тематических findings и TODO.

Особые случаи:

- Старый KNOWN_ISSUES связывал shadowing `bt/botest` с `@ts-nocheck` и выключенным
  TypeChecker. Свежие 12 compile-only проверок подтвердили ambient erasure bug
  script/module также без nocheck. Bare стирает объявления; TypeChecker создаётся.
  Причина — отсутствующая ambient-modifier фильтрация, а не выключенный анализ.
  [Минимальный source и текущий статус](../../compiler/findings.md).
- `process.exit()` в core остаётся существующим долгом. Направление для новой
  логики — вернуть результат/ошибку в CLI; перенос документации не исправляет код.
- Старые индексы TODO/ROADMAP не содержали самостоятельного контракта и больше
  не сохраняются вторыми действующими списками.
- Уникальность assert-сообщений была рекомендацией для диагностики, не требованием
  протокола botest; неверные npm-import и команды заменены проверенными workflow.

## Что нельзя было потерять

Сохранены причины отказа от throw-sentinel в finalizers, обход comma-update на C,
выбор IR и разделение lowering/passes, effect-order counterexamples и стоимость
output. Native `AB`/`012`, Check27Fixed `0FU1FU2FU|E` и C `OK: 60/60` имеют
ограниченную область: последнее — ручной bare smoke от 2026-10-07 без известной
версии C runtime. Они не означают полную C matrix, memory acceptance или полную
JS-семантику. Expression checkpoint с 10 PASS / 38 exact XFAIL сохраняет известные
расхождения, а не объявляет их исправленными.

Развитие script/module приостановлено до решения ownership/lifetime/циклов на
reference-counted C runtime. Defaults и регрессии остаются. Эта миграция не
разрешает возобновить env/descriptor ABI development.

В MCP/.NET сохранены standalone string ABI, crash при обратном Datex callback
с неустановленной причиной, различие physical files и SQL blobs, read grants по
MCP instance, отсутствие external atomic CAS и явный неизвестный исход timeout/Save.
Windows managed tests не становятся Windows HCM acceptance. XML Save не обещает
полную бизнес-операцию, авторизацию UI или rollback; SQL result limit не ограничивает
работу БД. Пробы, declarations и Datex описания имеют разную доказательную силу.

Все 30 не-Markdown evidence artifacts сохраняют точные bytes и относительное
расположение внутри комплектов; `.gitattributes` отключает EOL conversion.
Vendor runtime и приватные данные не добавляются. Абсолютные пути к недоступному
локальному vendor source представлены locators, с revision/hash где они были
известны; они не выдаются за переносимые гиперссылки.

## Проверка и границы завершения

Для завершения миграции каждый исходный материал должен иметь осмысленную судьбу:
сведения извлечены, запись сохранена как конкретное evidence/decision либо дубль
удалён с объяснением. Незакрытая работа описывается как конкретный технический
вопрос с основанием; общая задача «когда-нибудь разобрать архив» не считается
завершённой миграцией.

Проверяются сайт, локальные цели и навигация, original-source hashes, byte preservation,
комплектность карты, отсутствие старых каталогов и практические маршруты чтения.
Checker использует Markdown parser VitePress; он не устанавливает истинность
утверждений, не проверяет все anchors и не выполняет внешние HTTP запросы.
Локальная проверка сохранённых transcripts не является новым native запуском.

Известные runtime дефекты могут остаться открытыми после миграции документации.
Для них должны быть понятны утверждение, способ проверки, область применимости
и критерий закрытия. Возможность повторить все старые native эксперименты без
недоступной платформы не является условием переноса; отсутствие такой возможности
остаётся явной границей конкретного evidence.

## Как закрыты риски перехода

- Архив не оставлен будущей общей задачей. Old compiler reviews сопоставлены с
  source: fixed/superseded, confirmed defects, code-only risks и неподтверждённые
  performance/style предложения различаются в [findings](../../compiler/findings.md).
  В TODO остались конкретные технические задачи, не повторный разбор документации.
- Старые ADR сокращены там, где повторяли выдуманные API/schema, чеклисты реализации
  или неподтверждённую полную совместимость. Реальные причины/альтернативы сохранены;
  последующие изменения явно отделены от датированного решения.
- Публичные CLI инструкции сверены с source: actual config shape/defaults, bare
  onboarding, dev options, whole-push retry и один ZIP с components. Отдельный
  [CLI справочник](../../cli/README.md) сохраняет найденные defects и cache matrix.
- Все прежние guide/reference маршруты сайта сохранены; новые entrypoints не
  требуют читать внутреннюю историю. Npm/package README ссылаются на GitHub там,
  где source не входит в published package. Все внешние входящие anchors неизвестны;
  некоторые headings с неверным контрактом удалены намеренно.
- Copilot/Cursor удалены полностью. Полезный compiler/botest procedure извлечён
  в checkout-local skill; остальные общие знания доступны через AGENTS/refs.
  Переносимые skills остаются установимыми независимо от этого checkout.
- Восемь editor instructions и все 141 исходных ref/plans материалов учтены наряду
  с переписанными root/package snapshots и source-local refactoring note. В итоговой карте 157 записей; новые
  тематические страницы не изображаются исходными artifacts. Исходное намерение
  перехода доступно также в commit `b53db49` PR, постоянная корневая копия удалена.
- Три исторические битые ссылки ушли вместе с избыточными источниками;
  [реестр исключений](../../link-exceptions.json) пуст. Checker не принимает новые
  битые ссылки. Полный внешний link/anchor audit не заявлен.

Read-only dependency audit на дату миграции выявил moderate minimatch и low
fast-xml-parser advisory, без high/critical. Данные и cooldown dates записаны
[отдельно](../../cli/release-and-maintenance.md), текущая реализация и lockfile
в этом PR не обновлялись.

## Фактическая проверка результата

Локально после содержательной интеграции:

- `pnpm docs:test`: 17/17 positive/negative fixtures. Новые negatives ловят потерю
  root/editor/source-local записей карты, а не только материалов `ref/plans`.
- `pnpm docs:check`: 157 исходных записей, 30 byte-preserved artifacts, 0 исторических
  исключений. Проверены локальные цели и same-repository main GitHub links.
- `pnpm docs:build`, `pnpm format:check` и `pnpm lint`: exit 0. В ESLint остаются
  11 прежних unused warnings компилятора, без ошибок.
- Два сохранённых object-model verifiers: 59/59 и 53/53 recorded observations,
  transcript hashes и cleanup receipts; это offline-проверка исторических данных.
- SHA256 и `text: unset` attributes всех 30 artifacts проверены отдельно.
- Независимое content review сопоставило compiler/CLI summary с baseline; найденный
  пропуск про старые каталоги удалённых packages исправлен. Navigation review прошёл
  пять практических маршрутов и проверил renderer anchors 17 страниц сайта:
  166 fragment-ссылок, отсутствующих целей нет. Это ограниченная проверка anchors,
  а не обещание полного внешнего link audit.

Работы по миграции не оставлены отдельным следующим этапом. Открыты конкретные
runtime/compiler/tooling задачи из [TODO](../../../TODO.md); существующие результаты
не превращены в новую C/Windows HCM acceptance. Production logic, зависимости,
vendor sources и сохранённые пробы этим переходом не менялись. Изменения code
ограничены документационным checker/CI и двумя source comments с путями.
