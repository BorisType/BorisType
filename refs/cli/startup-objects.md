# Поставка отдельных документов при старте WebSoft

`btc link` добавляет отдельную внешнюю API-библиотеку. В Linux-дистрибутиве HCM 2025.2.1333 обработчик `OnAppInit` в `wtv/wtv_view_main.xml` открывает `source/api_ext.xml`, итерирует `apis/api/libs/lib/path` и вызывает `FetchDoc(path).SetShared()`. Это происходит также в клиентском контексте, поэтому в сгенерированном `OnInit` есть проверка `LdsIsServer`. Платформа оборачивает внешний цикл в `try/catch` и пишет `Error loading external API`. Ошибка объекта может остановить загрузку следующих внешних API и при этом HCM продолжит обслуживать запросы. Для CI с работающим сервером `btc push` передаёт ошибку загрузчика вызывающему процессу. [Линковка](../../packages/bt-cli/src/core/linking/startup-objects.ts) и [повторная инициализация](../../packages/bt-cli/src/core/pushing/reinit.ts).

Имя каталога версии зависит от содержимого native-библиотеки, имён и байтов XML. Это позволяет накатывать архив поверх предыдущей поставки. Старые файлы в других каталогах остаются на диске, но активный `init.xml` указывает только на новую версию. Имена объектов и план полей берутся из физического каталога при старте. Доступ к файлам идёт через `UrlToFilePath`, `ReadDirectoryByPath` и ограниченный `LoadFileDataRange`. Для регистраций сторонних приложений сборке нужен их исходный реестр. [Контракт поставки](../../docs/guides/startup-objects.md).

XML 1.0 читает стандартный `System.Xml.XmlReader` через штатный .NET-мост HCM. На стенде проверены запрет DTD, сохранение CDATA и точных десятичных ID, отклонение UTF-16/32 и невалидного UTF-8. Объект открывается по зарегистрированной форме. Node и cold start используют один native reader и тот же `object-patch.bs`, который реализует слияние типизированных элементов для MCP. Сравнение снимков выполняется до записи и после повторного открытия. Между последней проверкой и `Save()` остаётся окно конкурентной записи. [Мост HCM](https://wshcm-docs.boristype.dev/datex/common/7172076235998782946.html), [контракт патча](../mcp/xml-object-patch.md).

Создание использует `BindToDb(DefaultDb, Int(id))`. Второй аргумент присутствует в pinned declarations и подтверждён созданием документов на стенде. До обращения к хранилищу загрузчик проверяет обратимость `DocIDFromUrl(UrlFromDocID(Int(id)))`. На этом C-runtime исходный ID `9223372036854775809` превратился в ID `1` уже при построении URL, хотя `StrInt(Int(id))` сохранял исходную строку. Различие формы или необратимое преобразование завершают операцию. Для отсутствующей записи SQL-адаптер этого стенда возвращал `spxml_err:#2 Object not found` с точным ID. Для других ошибок чтения создание не выполняется. [BindToDb в справке](https://wshcm-docs.boristype.dev/news/platform/7144882497600254291.html#bindtodb), [wshcmx/types, lib/xmldocument/index.d.ts](https://github.com/wshcmx/types/blob/1d76d40c87ad6a9c249bd16f1bfea035dd815940/lib/xmldocument/index.d.ts).

## Приёмка 2026-11-24

Linux C-runtime, образ `websoft/hcm:2025.2.1333`, PostgreSQL, один сервер. Для воспроизведения на изолированной установке выберите два свободных точных ID. Изначально на этом стенде отсутствовали `source/api_ext.xml` и `wt/bt-startup-objects/`. Независимые чтения ниже использовали `OpenDoc(UrlFromDocID(Int(id)))` по SOAP.

1. В проекте с одним `package.json` и XML центра затрат были выполнены `btc link --clean --external-runtime` и `btc artifact --clean`. `objects apply --dry-run` вернул `would_create`. После распаковки ZIP и перезапуска контейнера в логе появился `created`. При чтении совпали ID, код и имя с кириллицей и амперсандом.
2. Командой `objects apply` в документ записаны комментарий, два keyed `custom_elem` и два unkeyed `subdivision`. Получены `would_update`, `updated` и `unchanged` при повторе. В физический каталог уже развёрнутой версии добавлен XML `server_agent`, отсутствовавший в ZIP. При старте он создан с `trigger_type=never` и `last_run_date=2024-02-29T12:30:01+00:00`. Центр затрат получил `unchanged`, сохранены комментарий и `doc_info.modification.date`.
3. Следующая поставка изменила имя, одно значение keyed-массива и явно передала один элемент unkeyed-массива. При холодном старте независимое чтение подтвердило сохранение непереданного комментария, кода и второго ключа, замену состава unkeyed-массива и штатное значение `is_active` после `bt-mode="clear"`.
4. Вызов `btc push` на работающем стенде и следующий холодный старт вернули объекты в состоянии `unchanged`. Для обоих путей проверены логи, для центра затрат также дата изменения. При добавлении неизвестного поля во второй XML push вернул ненулевой exit code, ID, фазу `validate` и `not_attempted`. Ожидавшее изменения поле первого документа сохранило прежнее значение.
5. Удаление всех определений с сохранением `objects/.gitkeep` снимает регистрацию при следующем полном деплое. Существующие записи сохранены. После проверки тестовые записи удалены по ID с проверкой уникального кода, файлы поставки убраны, стенд остановлен.

Локальные CLI-тесты проверяют согласованность сообщений, коллизии, повторы и потерю ответа. Приёмка на одном Linux C/PG не проверяет Windows, MSSQL, файловую БД, иной формат ошибок провайдера и конкурентный запуск нескольких узлов. [Сценарии CLI](../../packages/bt-cli/test/).

## Начальные значения в определении

Предложение для startup и `btc objects apply`. В текущей версии атрибут `default="true"` отклоняется. В старой ветке `deepCopyXmlTo` сначала обходил дочерние узлы, а на листе с `default="true"` пропускал запись при `targetField.Value !== null`. Эта проверка сама по себе не позволяет узнать, очищал ли администратор поле. [Старая реализация](https://github.com/BorisType/BorisType/blob/36cbb1937b148650e13cacc046552658ab3e788e/packages/builtin-runtime/src/objects.ts#L245-L255).

Предлагаемый синтаксис — флаг `default="true"` на поле в XML поставки. Для обычного скаляра без атрибута каждое применение приводит значение к указанному в XML. Например, `<name>Импорт заявок</name>` восстановит это название после ручного переименования. С записью `<name default="true">Импорт заявок</name>` название задаётся при создании документа. После этого сохраняется название со стенда, даже если администратор его очистил.

В элементе массива с ключом момент инициализации — создание самого элемента. Это позволяет добавить новую настройку в существующий объект. Флаг на контейнере распространяет условие на всё его поддерево. Пустая строка, ноль и `false` могут быть намеренными значениями. Если новая версия формы добавляет одиночное поле уже существующим документам, для их заполнения потребуется отдельная миграция. Способ объединения структур и массивов описывает `bt-mode`. [Правила XML-патча](../mcp/xml-object-patch.md).

| Сценарий                                                                       | Ожидаемый результат                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| У агента новая переменная `proxy`. В определении помечено только `wvar/value`. | При добавлении переменной по ключу `name` записать начальный `value`, даже если агент уже существует. В дальнейшем сохранить и пустой прокси на тесте, и реальный адрес на проде. Другие свойства переменной могут обновляться обычным патчем. |
| Список сотрудников группы задаёт обязательный минимум.                         | Достаточно существующего слияния по `collaborator_id`. Участники, добавленные в админке, сохраняются. Удалённый вручную участник из XML вернётся при следующем применении.                                                                     |
| XML задаёт только первоначальный состав группы.                                | Пометить контейнер `collaborators` целиком. Заполнить при создании группы, затем сохранять все ручные добавления и удаления, включая очистку списка.                                                                                           |

Основание примеров — структуры из остановленного Linux-образа HCM 2025.2.1333. `wtv_server_agent.xmd` наследует `web_variables_base`, где `wtv_general.xmd` задаёт `wvar MULTIPLE="1" PRIMARY-KEY="name"`. В `wtv_group.xmd` у `collaborators/collaborator` ключом служит `collaborator_id`. Для массива без ключа текущий патч заменяет переданный состав. Флаг на контейнере позволяет задать такой массив однократно. До реализации нужно определить диагностику неоднозначных сочетаний с `replace` и `replace-array` и проверить одинаковое поведение в предпросмотре, при старте и при повторе без `Save()`. [Действующие правила массивов](../mcp/xml-object-patch.md).
