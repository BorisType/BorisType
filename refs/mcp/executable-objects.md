Исследование 2026-11-20. Маршруты ниже сверены по поставке Linux HCM
2025.2.1333. Серверный и портальный маршруты выборки проверены на этой сборке.
Текущий `wshcm_run_agent` имеет отдельную [native-проверку](execution.md#запуск-существующего-серверного-агента).

| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server_agent`      | `wtv_server_agent.xms` вызывает `tools.start_agent` для сервера или `TopElem.run_agent()` для режима администратора.                                 | Серверный `run_agent` передаёт `OBJECT_ID`, `OBJECTS_ID_STR` и параметры потока. UI обрабатывает команды, диалоги и повторные шаги.                                                                                                                                                              |
| `statistic_rec`     | Кнопка проверки в `wtv_statistic_rec.xms` вызывает `ms_tools.calculate_statistic_rec_obj`.                                                           | Контекстный показатель вызывает `calculate_context` и возвращает значения расчёта, включая `value`, `value_str`, `value_desc`, `value_date` в методе формы. ## Выборки в LPE и через SOAP

По наблюдению пользователя кнопка **Проверка** может завершаться ошибкой у
выборок, которые получают часть окружения от LPE. Эталон для портального
сценария — вызов конкретного виджета в сессии портала. **Проверка** остаётся
дополнительным сравнением для серверного запуска.

Статическая сверка поставки 2025.2.1333:

- `wt/web/scripts/wt-lp.js` отправляет запросы виджетов в `lpe_data.html`.
  Пример из `WTLPItemList.NextPart` передаёт ID базового и переопределённого
  шаблонов, `object_id`, `mode`, параметры выборки и фильтры. `lpe_data.html`
  использует `Request.Session`, восстанавливает контекст страницы и вызывает
  `tools_web.insert_custom_code` для шаблона.
- `wt/web/view_block_grid.html` вызывает `_EvalCollection` из
  `wt/web/lpe_common_header.bs`. Этот код собирает `curObjectDoc`, тип страницы
  и `curContext` через `tools_lp.get_web_mode_context`; параметры могут
  приходить из шаблона, запроса и подстановок страницы. `_EvalCollection`
  добавляет `_curobject_id`, `_secid`, `_FILTERS`, `_SEARCH`, `_DISTINCTS`
  в соответствующих ветках и передаёт управление `TopElem.evaluate`.
- `wt/web/remote_collections_wsdl.xml` — отдельный штатный серверный маршрут.
  Он вызывает `evaluate` с текущим `Request` и служит отдельным вариантом
  для запуска по коду выборки. Подготовка контекста виджета выполняется в LPE.

Первый `wshcm_run_collection` предусматривает два режима. `server` принимает
`collectionId` и опциональный `objectId`. `lpe` принимает привязку виджета
к шаблону страницы и контекст страницы, включая `objectId`, если он нужен.
По одному ID выборки привязка не определяется однозначно. `params`,
`filters`, `search`, пагинация и сортировка сопоставляются с параметрами
выбранного маршрута. Например, в проверенном ItemList размер страницы
определяет настройка виджета.

`lpe` — экспериментальный режим с поддержкой проверенных типов виджетов.
Текст для описания инструмента:

> Experimental. Runs a supported LPE widget in the configured portal session.
> Returns the widget's data. An empty widget response can also occur after a
> collection error.

Ответ содержит строки, известные колонки и метаданные пагинации. Общий размер
выдачи передаётся при наличии в ответе HCM. Диагностика может указать режим,
объект, тип страницы и локаль. В `server` код и сообщение ошибки доступны
в выдаче HCM. В `lpe` транспортную ошибку и неожиданный формат можно
отличить от ответа виджета. Нулевая выдача проверенного виджета означает
нулевое число отображённых строк, исход самой выборки в таком случае неизвестен.

Первая версия `lpe` использует одну настроенную авторизованную сессию
портала. Именованные сессии для проверки разных ролей остаются предметом
отдельного исследования. `objectId` и параметры выборки задают предмет
расчёта. `iPersonIDParam` в админской обёртке создаёт вычислительный
контекст, а права зависят от выбранного маршрута HCM.
[Аутентификация на портале](https://wshcm-docs.boristype.dev/news/open-components/7290461379270899374.html)

### Нативная проба ItemList 2026-11-20

Linux C-runtime HCM 2025.2.1333, PostgreSQL, image `0edeac24afc2`. В Chrome
открыли `/news` и зафиксировали POST виджета в `/lpe_data.html`. Для повтора
в отдельном Node HTTP-клиенте вошли тестовой учётной записью на `/news`,
сохранили сессию и передали идентификаторы обоих шаблонов, `mode`, `refresh=1`
и `datapage=1`. Тело запроса имело формат `application/x-www-form-urlencoded`.
Запрос первой загрузки также передавал `deferred=1`, `firstreq=1`,
`pageindex=1` и `filters`. Ответ имел `Content-Type: text/html`, фактический
формат — JSON в `UrlEncode16`, включая последовательности `%uXXXX`.
После декодирования совпали все 12 ID и показанная виджетом пагинация.
Фильтр поиска `HR` сократил результат до шести строк. В анонимном запросе
получили HTTP 401, при неверной привязке шаблона — HTTP 500.

Для второй пробы создали временные `statistic_rec`, `web_mode`,
`remote_collection` и копию OWT ItemList. Показатель зарегистрировали в
`web_mode.statistic_recs` с кодом, общим для пробных объектов. Его код:

```js
VALUE_STR = "ctx:" + StrInt(OBJECT_ID);
VALUE = -7;
```

Выборка искала запись этого показателя в `curContext` по полю `name`,
возвращала `value_str`, текущие ID и значение объявленного `bt_lpe_param`.
Она выставляла `PAGING.MANUAL = true`, возвращала семь синтетических строк
или пять при наличии `probe-filter` в `_FILTERS` и выбирала окно по
`PAGING.INDEX` и `PAGING.SIZE`. Размер виджета задали через `rows_in_page=2`
и `items_in_row=1`. Сценарий с `pageindex=2` и фильтром вернул две строки
из пяти, точные ID `9007199254740995` и `9007199254740996` строками,
`PAGING.INDEX=1` и значение показателя для переданного объекта. Перекрытие
`bt_lpe_param` через `collection_params` заменило шаблонное «из шаблона»
на «из запроса» в строке выборки. При вызове той же выборки через
`ms_tools.evaluate_remote_collection_obj` в SOAP `curContext` отсутствовал,
а `bt_lpe_param` имел значение `definition-default`.

Для отказа сохранили код `ERROR = 154; MESSAGE = 'Probe rejection'; RESULT = [];`.
SOAP вернул код 154 и сообщение. ItemList вернул HTTP 200 с пустым `aResult`
и `iTotal: 0`. После запуска с успешным `PAGING.MANUAL = true; PAGING.TOTAL = 0; RESULT = [];`
SHA-256 декодированного ответа ItemList совпал. Поля ошибки теряются на
уровне виджета. Для строгого контракта ошибок требуется доступ к результату
`evaluate` внутри того же контекста LPE до преобразования в ответ виджета.

Пробные `.bs` читались с UTF-8 BOM. Путь к файлу и код у временных объектов
сохранялись через заполненную XMD-форму с `AssignElem`. Прямые присваивания
`script` и `url` в этой пробе оставили поля пустыми. Удалены четыре пробных
объекта и два файла, отсутствие проверено повторным запросом. Стенд остановлен.
Мультинодовая работа, другие виджеты и схемы входа на портал требуют своих проб.
[Как устроена выборка](https://wshcm-docs.boristype.dev/news/monolith/6683736610977116379.html)
· [Как LPE использует шаблоны](https://wshcm-docs.boristype.dev/news/platform/7262396569512541394.html)
· [Проверки доступа](https://wshcm-docs.boristype.dev/news/platform/7224157877135306854.html)

В SOAP-адаптере окружение следует собирать из аутентифицированного пользователя,
явного ID контекстного объекта и параметров вызова. В штатной обёртке выборки
`iObjectIDParam` попадает в `Request.Session.Env` только на ветке с переданным
`iPersonIDParam`; другая ветка получает запрос через `tools_web.get_admin_request`.
Нужно проверить контекст объекта отдельно от выбора пользователя и сохранить
встроенную проверку `tools_web.check_access`.

## Границы запуска других объектов

Контракт каждого инструмента должен назвать штатную точку входа и этап,
для которого доступен результат. Для удалённого действия это может быть
один серверный шаг с описанием следующей команды интерфейса. Для показателя
важно указать контекст расчёта и отдельно описать сохранение данных и даты
расчёта. `ended` у агента означает завершение потока; прикладной результат
проверяется по данным, которые агент записал или вывел в журнал.

Для клиентского запуска агента первый тест проходит через кнопку **Выполнить
агент на стороне клиента** в реальной сессии веб-админки. Следует измерить
`LdsIsServer`, наличие `ActiveScreen` и место появления метки. Результат
установит, какой runtime выполняет этот путь в веб-клиенте данной версии.
[Ручной запуск агента](https://wshcm-docs.boristype.dev/news/monolith/6778683164024335400.html)
