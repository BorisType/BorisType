# Что такое BorisType?

BorisType — набор инструментов для работы с **WebSoft HCM**. В него входят MCP
сервер, .NET библиотеки, agent skills и компилятор ограниченного подмножества
TypeScript в BorisScript. Эти направления можно использовать по отдельности.

## MCP, библиотеки и skills

[MCP сервер](./mcp-server) работает в Node.js и соединяется с WebSoft HCM.
Девять файловых tools используют отдельно установленную `BorisType.FileSystem.dll`
**0.1.0-alpha.4 / API 2**. Серверный XQuery и три XML tools не используют эту DLL.
Сборка MCP не требует компилятора TypeScript → BorisScript.

Файловые tools работают с физическими файлами. Платформенный URL может вести к
SQL blob, содержимое которого отличается от файла на диске. Учёт чтений перед
правкой не даёт атомарной защиты от внешних изменений или изоляции чатов.
Контракты и ограничения приведены в [руководстве MCP](./mcp-server).

[Skills](./agent-skills) устанавливаются независимо. Они содержат инструкции и
ссылки на источники, но не устанавливают сервер или DLL. Применение инструкций
зависит от клиента и агента.

## Компилятор TypeScript → BorisScript

BorisScript похож синтаксисом на JavaScript, однако имеет собственную семантику
и ограничения. Компилятор преобразует **ограниченное подмножество TypeScript**;
он не гарантирует полную совместимость с ECMAScript или npm-библиотеками.
Поддержка зависит от режима и формы выражения. Перед выбором синтаксиса сверяйтесь
со [справочником ограничений](../reference/borisscript-constraints).

С 2026-11-05 поддерживаемое направление разработки — **bare**. Развитие
`script` и `module` приостановлено до решения стратегии памяти C-runtime;
реализации и регрессионные проверки сохранены. **CLI по умолчанию всё ещё
использует `module`.** Для bare укажите режим явно:

```sh
npx btc build --compile-mode bare
```

Bare не предоставляет общую инфраструктуру модулей, closures и polyfills.
Подробнее о выборе режима и приоритете директив — в
[справочнике режимов](../reference/compile-modes).

Существующий экспериментальный module pipeline включает компиляцию в `build/`,
[линковку](./linking) в `dist/`, создание [артефактов](../reference/artifact-command)
и [push на сервер](./push-deploy). [Dev mode](./dev-mode) объединяет watch,
сборку, линковку и auto-push. [Botest](./testing) выполняет проверки в Node.js;
результат эмуляции не доказывает поведение C-runtime HCM.
