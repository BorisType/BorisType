# Dev Mode (Watch & Auto-Deploy)

`btc dev` объединяет watch, сборку, линковку и optional push существующего
экспериментального module pipeline. Развитие `script/module` заморожено до
решения стратегии памяти; CLI default сохранён. См. [режимы](../reference/compile-modes).

## Базовое использование

Для локальной работы:

```sh
npx btc dev --no-push
```

Для автоматической загрузки на настроенный сервер:

```sh
npx btc dev
```

**Auto-push включён по умолчанию** и использует `btconfig.properties` из текущей
директории. Флаги подключения команды `push` у `dev` отсутствуют. Нет и флага
`--compile-mode`: отдельный bare-файл выбирается через `/// @bt-mode bare`.

## Координация мультипакетных проектов

```json
{
  "linking": {
    "packages": [{ "name": "backend" }, { "name": "frontend" }]
  }
}
```

Для каждого отслеживаемого пакета запускается свой TypeScript watcher.
После успешной начальной сборки всех таких пакетов выполняется полная линковка,
затем изменения пересобираются и линкуются инкрементально.
`ws:name` пакетов должны различаться: координатор использует их как ключи.

## Фильтрация пакетов

Отслеживаются перечисленные для линковки пакеты с `ws:package`, `ws:name` и
`tsconfig.json`. `library`/`lib`, обычные статические директории и пакеты без
metadata не получают собственный watcher. Их нужно собирать/копировать отдельно
и выполнять полную линковку. Отсутствующий `tsconfig.json` у выбранного пакета
может заблокировать начальную линковку: запустите отдельный `btc build` и проверьте логи.

## Инкрементальные сборки

TypeScript определяет affected files; это могут быть и зависимые файлы.
Текстовые non-TS файлы копируются при старте; watcher обрабатывает add/change/unlink.
После пересборки standalone/component линкеры копируют изменённый output,
пропуская обновление их `node_modules`.

После изменения зависимостей, `package.json`, `btconfig.json` или путей output
остановите `dev`, соберите нужные пакеты и выполните `btc link --clean`.
Перезапуск нужен также после изменения набора пакетов и non-TS watch roots.
Не рассчитывайте на полное удаление старых файлов из `dist/` при unlink/rename.
После удаления исходников очистите их старый output перед полной линковкой.

В multi-package watch текущая инкрементальная линковка может потерять остальные
записи `api_ext.xml`; при явных `source`/`target` она также может использовать
пути по умолчанию. Для итоговой поставки остановите watch и выполните полную
линковку из корня проекта.

## Авто-push

Очередь ждёт 500 мс после последнего запроса. Одновременно выполняется один push;
изменение во время него планирует следующий. Сессия инициализируется лениво
и переиспользует клиент/evaluator. Загрузка отправляет весь `dist/`, даже после
инкрементальной линковки. Ошибки выводятся в лог; новый успешный push не является
гарантией корректной инициализации каждого модуля.

## Жизненный цикл

```text
watch → успешные начальные сборки → полный link → optional push
      → affected build / non-TS change → incremental link → optional push
```

`Ctrl+C` закрывает watchers и evaluator. Watch не предоставляет hot module
replacement с сохранением состояния приложения.

## Устранение проблем

### Некоторые пакеты не пересобираются

Проверьте `linking.packages`, `ws:package`, `ws:name` и `tsconfig.json` каждого
пакета. Library и статические директории требуют отдельного действия.

### Изменения не отправляются

Проверьте отсутствие `--no-push`, параметры соединения и логи upload/reinit.
Для воспроизведения сначала выполните отдельные `build`, `link --clean`, `push`.

### Начальная сборка зависла

Координатор ждёт успешную сборку каждого выбранного пакета. Ошибки TypeScript,
пропущенный watcher или одинаковые `ws:name` мешают этому условию.
