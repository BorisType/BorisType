# Служебные объекты при запуске HCM

Храните определение каждого объекта в Git рядом с кодом. Например, для центра затрат создайте файл `objects/cost_center/9007199254740993.xml` в проекте с `package.json`. Выберите свободный стабильный ID для своей установки. Для агента каталог называется `objects/server_agent/`.

```xml
<cost_center>
  <code>engineering</code>
  <name>Разработка</name>
</cost_center>
```

## Собрать и поставить

```sh
npx btc link --clean --external-runtime
npx btc artifact --clean
```

В CI достаточно этих двух команд для проекта из одних XML. Проект с TypeScript собирайте своей обычной командой перед линковкой. `btc link` ищет XML в `objects/<тип>/<ID>.xml` у корня проекта и у подключённых пользовательских пакетов `standalone` и `component`. ID задаётся положительным десятичным числом до `18446744073709551615` включительно и должен быть уникальным во всей поставке. На проверенном C-runtime HCM 2025.2.1333 значения выше `9223372036854775807` теряют старший бит при построении URL. Загрузчик отклоняет ID, если платформа не может восстановить его по полученному URL. Корневой элемент XML должен совпадать с именем каталога. Если в XML есть поле `id`, оно должно обозначать тот же объект.

Разверните содержимое `artifact/main.zip` в каталоге установки WebSoft до запуска сервера. Архив содержит `source/api_ext.xml`, сгенерированный `init.xml`, серверную библиотеку и XML-файлы в `wt/bt-startup-objects/`. Загрузчик перечисляет каталог активной версии **на сервере при каждом старте**. Определения из старых версий в соседних каталогах в обход не попадают.

`source/api_ext.xml` общий для установки. Если на стенде уже зарегистрированы сторонние API, включите исходный реестр в поставку через mapping `source`/`target` в `btconfig.json`. Линковщик объединяет записи из поставляемого реестра. Распаковка поверх сервера заменяет файл по этому пути. Перед рестартом разверните все файлы версии. После изменения XML в проекте снова выполните полный `btc link`. Чтобы снять последнюю регистрацию при поставке из чистого CI checkout, оставьте в корневой папке `objects/` один файл `.gitkeep` и разверните новый артефакт.

## Что произойдёт с записью

| Состояние                                                             | Действие                                                                                  |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| ID свободен                                                           | Создаётся документ по форме указанного типа с этим ID и штатными значениями по умолчанию. |
| ID занят документом ожидаемой формы                                   | Обновляются переданные поля. Остальные значения сохраняются.                              |
| Значения уже совпадают                                                | Загрузчик пропускает `Save()`.                                                            |
| ID занят другим типом, расходится форма или поле невозможно применить | Загрузчик сообщает ошибку с контекстом объекта.                                           |
| XML убран из активной поставки                                        | Документ остаётся в базе.                                                                 |

Для `MULTIPLE` с `PRIMARY-KEY` элементы по умолчанию объединяются по ключу. Для `MULTIPLE` без ключа переданные элементы задают полное содержимое массива. Контролы `bt-mode` позволяют явно очистить поле, заменить массив или удалить элемент по ключу. Атрибут `default="true"` из экспериментальной ветки отклоняется как неизвестный. Правила дат, целых чисел и native defaults общие с точечным редактированием объектов через MCP. [Контракт XML-патча](../reference/mcp-objects)

Загрузчик использует штатный .NET-мост HCM и стандартные сборки `mscorlib`, `System.Xml` и `System.Text.RegularExpressions`. Проверен Linux C-runtime HCM 2025.2.1333 с PostgreSQL. XML сначала проверяется для всей поставки. Обработка нескольких документов использует отдельный `Save()` для каждого. Ошибка во время записи может оставить часть объектов применёнными. Для кластера планируйте установку с одним пишущим узлом. Платформа может продолжить запуск при ошибке внешней библиотеки. В журнале запуска ищите `BorisType objects`, путь к XML и статус операции. Ошибка внешней API-библиотеки может также прервать инициализацию следующих внешних API. Проверяйте состояние нужных объектов.

## Проверить один файл на работающем стенде

```sh
npx btc objects apply objects/cost_center/9007199254740993.xml --dry-run
npx btc objects apply objects/cost_center/9007199254740993.xml
```

Подключение берётся из `btconfig.properties` в текущем каталоге. Доступны `--host`, `--port`, `--https`, `--username` и `--password`. Размер файла ограничен 256 КиБ, кодировка UTF-8. Предпросмотр проверяет данные по форме и текущей записи на целевом стенде.

Команда печатает JSON. При предпросмотре возможны `would_create`, `would_update` и `unchanged`. При применении — `created`, `updated` и `unchanged`. При ошибке код завершения ненулевой. Если ответ сервера потерян, запись могла завершиться. Прочитайте документ или повторите предпросмотр перед следующим применением.
