# Каталоги, формы и документы

Чтобы найти и поменять запись, нужны три разных результата. Реестр даёт имя каталога, [XQuery](./mcp-execution#wshcm-xquery) находит в нём ID, полное чтение документа даёт XML и токен для записи. Если ID уже известен, начинайте с `wshcm_get_object`. Во всех аргументах `id` передавайте точную положительную десятичную строку, например `"9007199254740993"`. Это правило распространяется и на ID, который поместился бы в число JSON.

## wshcm_list_object_types

Найти зарегистрированный тип документа, его форму и связанные каталоги. Без аргументов возвращается страница обоих реестров. `kind` принимает `object` или `catalog`, `objectType` задаёт точный тип документа. Например, следующий вызов помогает найти `cost_center` и каталог `cost_centers`.

```json
{ "objectType": "cost_center", "limit": 20 }
```

Ответ содержит `items`, `offset`, `limit`, `total` и `sources`. Начало — 0, размер страницы по умолчанию 100, максимум 250. У записи есть `kind`, `name`, `isCustom`, могут быть `formUrl`, `title`, `isHier`. У каталога `objectType` может отсутствовать или быть `null`. Проверьте `sources.registeredCatalogs`: при `unavailable` эта установка не предоставила список каталогов. `not_requested` означает, что источник исключил фильтр.

Берите `formUrl` из найденной записи, а имя каталога для запроса — из `name` строки `kind: "catalog"`. Признак `supportsCustomFields` отражает наличие `custom_elems` в форме. За списком фактически настроенных полей перейдите к [определениям](./mcp-custom-fields#wshcm-get-custom-field-definitions).

## wshcm_list_object_data_types

Найти определения из `object_data_types`, когда нужно понять, какие дополнительные данные могут связываться с объектом. Пустой ввод перечисляет все определения. `objectType` ищет по обеим сторонам, `primaryObjectType` и `secondaryObjectType` фиксируют сторону. Если задать несколько фильтров, должны выполниться все.

```json
{ "objectType": "subdivision", "offset": 0, "limit": 25 }
```

В `items` приходят `id`, `code`, `name`, `primaryObjectType`, `secondaryObjectType`. У незаданной стороны значение `null`. Одно определение, подходящее по обеим сторонам, занимает одну строку. Страница по умолчанию 100, максимум 250, `total` учитывает фильтры. Чтобы получить записи этого типа, используйте `wshcm_xquery` по `object_datas` с условием на `object_data_type_id`. Чтобы узнать настроенные для него поля, передайте его ID в `scope: {objectType: "object_data_type", templateId: id}` при чтении определений.

## wshcm_get_form

Прочитать загруженную HCM форму, например перед созданием документа. Обязателен `formUrl` с локальным XMD URL (`x-local://` или `x-app://`).

```json
{ "formUrl": "x-local://wtv/wtv_cost_center.xmd" }
```

По умолчанию возвращает `formUrl`, имя корневого элемента `root` и строку `xml`. После декодирования JSON в `xml` уже находится XML загруженной формы с раскрытым платформой наследованием. Его можно использовать для поиска имён полей, типов и ключей массивов. Отдельные зависимости и кэш принадлежат HCM, а загрузка формы может выполнять код. Настроенные шаблоны читаются отдельно от XMD.

## wshcm_get_object

Получить текущее содержимое одной записи перед правкой или удалением.

```json
{ "id": "9007199254740993" }
```

По умолчанию в ответе `id`, `formUrl`, `root`, полный экспортируемый `xml` и `readToken`. При превышении лимита XML или схемы в 256 KiB чтение завершается ошибкой. Для работы с конкретной версией документа храните последний токен этого ID в этом экземпляре MCP. Его срок — 30 минут, одновременно хранится до 32 снимков. Новое чтение того же ID заменяет токен. Экспорт охватывает содержимое `TopElem.Xml`. Бинарные ресурсы, временные поля и вычисляемые данные требуют отдельного учёта.

### Редактирование через локальный XML

Чтобы поправить XML скриптом, вызовите `wshcm_get_object` с именем нового файла в проекте. Для существующей подпапки пример выглядит так.

```json
{ "id": "9007199254740993", "outputPath": "objects/center.xml" }
```

Ответ содержит абсолютный `file.path` на машине MCP и `readToken`. Отредактируйте файл и отправьте полную версию через `wshcm_save_object` в том же экземпляре MCP.

```json
{ "mode": "replace", "id": "9007199254740993", "readToken": "<readToken>", "inputPath": "objects/center.xml" }
```

MCP сверяет исходный снимок документа и формы с HCM. Правка локального файла сохраняет пригодность токена до обычного срока истечения. При конфликте прочитайте свежую версию, перенесите свою правку и используйте новый токен.

| Инструмент                                | Вход и результат                                                                                                                                                                                                                               |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wshcm_get_object`, `wshcm_get_form`      | По умолчанию возвращают строку `xml`. С `outputMode: "file"` возвращают XML в новом временном файле. Для формы это раскрытая XMD, также с расширением `.xml`.                                                                                  |
| `wshcm_patch_object`, `wshcm_save_object` | Передайте ровно один из `xml` и `inputPath`. Для строки ответ по умолчанию содержит `xml`, для файла — `file`. Режим можно выбрать явно через `outputMode`. Preview patch возвращает полного кандидата, успешный Save — перечитанный документ. |

Во всех четырёх вызовах `outputPath` включает файловый режим и требует свободного имени. Каталог проекта должен существовать. Относительные пути считаются от единственного локального корня проекта. При нескольких корнях укажите абсолютный путь. Если клиент их не передаёт, задайте `--project-directory` при запуске MCP.

Временный XML попадает в `~/.boristype/shared/objects` (корень меняет `--shared-directory`). У него `file.storage: "shared"`, срок `expiresAt` через 24 часа с создания и предупреждение. Для долгого хранения используйте проектный `outputPath` или скопируйте файл в проект до истечения срока. Там `file.storage: "project"`, жизненным циклом управляет владелец проекта. Для файла действуют тот же лимит в 256 KiB и кодировка UTF-8. Если локальный вывод сорвался после подтверждённого сохранения, ответ содержит `writeStatus: "saved"` и ID. Прочитайте объект по ID, чтобы получить результат.

## wshcm_patch_object

Изменить выбранные поля существующей записи. Подставьте ID и свежий токен из `wshcm_get_object`. Корень `xml` должен совпадать с корнем документа. Здесь показан предпросмотр смены названия с сохранением кода и остальных полей.

```json
{
  "id": "9007199254740993",
  "readToken": "<readToken>",
  "xml": "<cost_center><name>Учебный центр</name></cost_center>",
  "dryRun": true
}
```

| Что передано в XML                 | Что произойдёт                                                                                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Скаляр или вложенная структура     | Указанные поля обновятся. Отсутствующие соседи сохранятся. Пустой элемент с `bt-mode="clear"` сбрасывает значение с учётом defaults формы.                                  |
| Элемент `MULTIPLE` с `PRIMARY-KEY` | Укажите ключ. Существующий элемент обновится на месте, новый добавится в конец. `bt-mode="remove"` с одним ключом удаляет элемент.                                          |
| Элементы `MULTIPLE` без ключа      | Перечислите **весь** новый состав одноимённой группы в нужном порядке. Один пустой элемент создаёт пустое значение. Один пустой элемент с `bt-mode="clear"` очищает группу. |
| `bt-mode="replace"`                | Заменяет содержимое указанной структуры или одного выбранного по ключу элемента.                                                                                            |
| `bt-mode="replace-array"`          | Поставьте атрибут на первый элемент группы и перечислите весь новый состав. Соседние группы сохранятся.                                                                     |

Поддерживаются string, integer, bool, real и XML date. Дата задаёт календарное время HCM с точностью до секунды. Для воспроизведения значения берите текст из XML. Суффикс `+00:00` у такого значения не задаёт преобразование часового пояса. Ненулевые смещения и ненулевые дробные секунды отклоняются. Вход ограничен 8 192 элементами и глубиной 64.

В ответе есть `changed`, `dryRun`, `writeStatus` и `xml`. Для preview это XML кандидата. **Предпросмотр расходует токен.** Для применения перечитайте запись, сравните её с исходной и вызовите patch со свежим токеном и `dryRun: false`. Если изменения отсутствуют, Save пропускается. При `saved` возвращается XML повторного чтения с учётом обработчиков HCM. После каждой обработанной попытки, включая ошибочный XML, требуется новое чтение.

## wshcm_save_object

Создать запись или полностью заменить уже существующую. Для создания требуются `mode: "create"`, `formUrl` и полный `xml`. ID выделяет платформа.

```json
{
  "mode": "create",
  "formUrl": "x-local://wtv/wtv_cost_center.xmd",
  "xml": "<cost_center><code>training-center</code><name>Учебный центр</name></cost_center>"
}
```

Для замены передайте `mode: "replace"`, `id`, `readToken` и полный `xml`. Используется фактическая форма прочитанного объекта. **Пропущенные поля очищаются или получают defaults.** При намерении сохранить соседние поля выберите patch. Проверяются синтаксис, корень, ID, пути полей, кратность и представление integer. Остальные преобразования выполняет платформа.

При успехе ответ содержит `id`, `formUrl`, `root`, `xml` и `writeStatus: "saved"`. В ошибке `not_attempted` означает, что Save ещё не вызывался, `unknown` требует проверить фактическую запись, `saved` возможен при сбое чтения уже сохранённого объекта. Известный ID сохраняется в ошибке. При потере ответа на create ищите запись по ожидаемому уникальному коду до повторного вызова. Сравнение снимка перед записью и Save выполняются последовательно. Бизнес-действия веб-админки могут включать дополнительные шаги.

## wshcm_delete_object

Переместить прочитанный документ в корзину HCM. Нужны ID и свежий токен полного чтения.

```json
{ "id": "9007199254740993", "readToken": "<readToken>" }
```

Перед вызовом удаления сверяются документ и форма, попытка расходует токен. Успех возвращает `{id, mode: "trash", deleteStatus: "deleted"}`. Это подтверждение штатного вызова удаления. Судьба связанных записей и бинарных ресурсов зависит от типа объекта и его обработчиков. При `deleteStatus: "unknown"` проверьте основной каталог и корзину до нового вызова.
