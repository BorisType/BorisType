# Стенд, запросы и выполнение кода

Для проверки подключения начните со сводки стенда. Для чтения строк каталога используйте XQuery, для разового библиотечного вызова — BorisScript, для запуска уже настроенного агента — его ID. Все эти операции выполняются на стороне HCM под настроенной учётной записью. Файловая DLL нужна только при работе с физическими файлами.

## wshcm_get_system_info

Получить сведения из окна «О программе → Информация о системе». Для первого вызова достаточно пустого объекта.

```json
{}
```

Ответ содержит объект `summary` с `hcmVersion`, `osVersion`, `database.type`, `database.version`, `unibridgeVersion`, `runMode` и признаками `cluster`, `fullTextIndex`, `personalData`. Неизвестное значение даёт `null`. Передайте `includeReport: true`, если нужны исходные секции INI, XML и Global Settings. В поле `report` поступает штатный текст, включая параметры конфигурации, без дополнительной очистки. Если исходный отчёт превышает 256 KiB UTF-8, сервер отклоняет его целиком даже при запросе сводки. Сведения относятся к ответившему процессу.

## wshcm_runtime_status

Подготовить и проверить поставляемый комплект BorisType.FileSystem на HCM. Отдельный вызов нужен для диагностики, поскольку файловые операции сами выполняют такую подготовку.

```json
{}
```

В ответе `expected` описывает требуемую сборку, `installed` — установленную на диске, `loaded` — фактически загруженную в процесс. Поля `changed`, `process` и `reason` помогают понять, куда попал запрос и что произошло. Подготовка может записать файлы и загрузить сборки.

| `status`           | Действие                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `ready`            | Можно вызывать файловые инструменты на этом процессе.                                                                               |
| `restart_required` | На диске подготовлена нужная сборка. Ответивший процесс использует другую. После перезапуска этого процесса повторите проверку.     |
| `blocked`          | Прочитайте `reason` и сведения о сборках. Среди возможных причин — доступ к каталогу DLL, несовместимый API или повреждённые файлы. |

При ошибке подготовки файловый вызов может вернуть `error.code: "RuntimeNotReady"` и вложенный `runtimeStatus`. При таймауте подготовка может продолжиться. За балансировщиком два запроса могут попасть в разные процессы. Для сведений о версии самой HCM используйте `wshcm_get_system_info`. [Подготовка .NET на HCM](../guides/dotnet)

## wshcm_xquery

Отправить платформе серверный XQuery или SQL с префиксом `sql:`. Обязательный параметр — `query` до 64 KiB UTF-8. Пример находит запись по коду. Имя каталога можно получить через [реестр типов](./mcp-objects#wshcm-list-object-types).

```json
{ "query": "for $c in cost_centers where $c/code = 'training-center' return $c", "maxRows": 10 }
```

`rows` содержит проекции строк, `returnedRows` — фактически выданное количество. `maxRows` по умолчанию 100, диапазон 1–1000. При `truncated: true` проверьте `limitReason`: `rows` означает ограничение числа строк, `output` — размера выдачи. Для продолжения задайте порядок и условие следующего диапазона в самом запросе. Готового курсора инструмент не выдаёт. Размер ответа до 256 KiB. Фильтрация в запросе уменьшает объём работы БД, ограничение возвращаемых строк само по себе такого обещания не даёт.

Безопасный integer становится числом JSON, больший по модулю — точной десятичной строкой. При передаче ID в инструменты объектов используйте строку. Конечный real выдаётся как число с возможной потерей точности при форматировании SOAP. Даты проецируются в строки, XML-элементы — в значения, записи и массивы. Для исходного XML документа используйте `wshcm_get_object`.

На проверенной Linux HCM 2025.2.1333 с PostgreSQL отрицательный SQL integer мог стать `null` на этапе SQL→XML, а SQL NULL и пустая строка — совпасть. Если знак существенен, преобразуйте значение в текст внутри SQL, например `sql: SELECT CAST(-7 AS VARCHAR(32)) AS signed_value`. Запрос передаётся платформе как есть и может менять данные. Ошибка ответа или таймаут не доказывают отмену запроса. [Матрица типов и границы SQL→XML](./ws-client-values)

## wshcm_execute

Выполнить фрагмент серверного BorisScript, вызвать библиотеку, получить возвращаемое значение и диагностику. Единственный аргумент — `code`, до 64 KiB UTF-8. Например, можно узнать версию WTV через её библиотеку.

```json
{ "code": "print('Проверка WTV'); return tools.get_version('wtv', false);" }
```

При успехе результат имеет такую форму (версия зависит от стенда):

```json
{ "ok": true, "value": "2025.2.1333", "output": ["Проверка WTV"], "outputTruncated": false }
```

`return` задаёт `value`. Экспериментальная функция `print(value)` добавляет одно сообщение в `output` текущего вызова и возвращает свой аргумент. Строка сохраняется как есть, прочие значения форматируются платформой. Штатные `alert` и записи библиотек остаются в журналах HCM. При переполнении (до 256 сообщений и 16 000 закодированных символов) выставляется `outputTruncated`, скрипт продолжает работу.

Для результата действуют правила integer/real и проекции XML из XQuery, `undefined` превращается в `null`, неконечные real вызывают ошибку представления. Предел проекции — 32 уровня, 10 000 значений и 48 000 символов внутреннего представления. Максимум ответа — 256 KiB.

При `isError: true` посмотрите `error.phase`. Значение `execution` означает ошибку разбора или выполнения, `result` — ошибку подготовки возвращаемого значения, `presentation` — ошибку представления в MCP. Уже собранный вывод сохраняется для этих ошибок. Сбой транспорта или ответа имеет верхнеуровневую `phase` и `executionStatus`. При `not_started` отправка не состоялась. При `unknown` сначала проверьте фактический эффект. Код работает с правами аккаунта HCM, может менять данные, а таймаут клиента **не останавливает** выполнение.

## wshcm_run_agent

Запустить существующий BorisScript-агент на standalone HCM. Нужен `agentId` записи `server_agent`. Если ID неизвестен, найдите его через каталог и XQuery. Кластерная роль и роль web-сервера отклоняются при подготовке. Инструмент воспроизводит серверный запуск, для которого агент определил код и параметры.

```json
{ "agentId": "9007199254740993", "objectId": "9007199254740995", "mode": "sync", "waitTimeoutMs": 5000 }
```

`objectId` доступен агенту как `OBJECT_ID`. `objectIds` принимает до 256 ID и передаёт их через `OBJECTS_ID_STR` с разделителем `;`. `params` — до 32 объявленных агентом параметров со строковыми значениями. Они меняются только на один запуск. Необъявленный параметр даёт ошибку до запуска.

В режиме `async` (по умолчанию) ответ `{agentId,status:"accepted"}` подтверждает передачу на выполнение. Режим `sync` ждёт поток до `waitTimeoutMs` (1–20 000 мс, по умолчанию 5 000). `ended` подтверждает завершение потока, `wait_timeout` — истечение ожидания. Чтобы подтвердить прикладной результат, прочитайте ожидаемую запись или другой эффект агента. На ошибке доступны `agentId`, `phase`, `error` и `executionStatus`. После неизвестного исхода или `wait_timeout` повторный запуск может создать вторую операцию.
