# Пакеты объектов и ZIP

Для разового переноса достаточно трёх вызовов. На исходном стенде `wshcm_export_package` собирает ZIP по ID. На целевом стенде `wshcm_inspect_package` показывает состав, а `wshcm_import_package` применяет выбранное. Если набор понадобится снова, создайте именованную схему и редактируйте её состав. Эти операции адресуют схему по `schemaId` и сохраняют текущий выбор в веб-админке.

| Значение                                    | Где действует и для чего нужно                                                                                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaId` и `revision`                     | Именованная схема HCM и снимок общего документа схем, прочитанный в данном экземпляре MCP.                                                                    |
| `artifact.artifactId`, `artifact.localPath` | ZIP на машине **процесса MCP**. Handle действует 24 часа, файл сохраняется на диске.                                                                          |
| `exportPath`                                | Абсолютный путь к готовому ZIP для передачи между проектами и стендами.                                                                                       |
| `inspectionId`                              | Проверенный неизменяемый снимок архива для импорта на целевом стенде в этом экземпляре MCP. После перезапуска повторите просмотр.                             |
| `operationId`                               | UUID одной операции. Назначьте его до вызова, если понадобится узнать исход после таймаута. Для следующей операции с побочными эффектами возьмите новый UUID. |

Все ID объектов передавайте положительными десятичными строками. Для UUID допустим любой регистр, в ответе они приводятся к нижнему. У `schemaId` и `packageId` регистр значим. В примерах замените обозначения в угловых скобках значениями из предыдущего ответа.

## wshcm_list_package_schemas

Просмотреть сохранённые схемы и выбрать нужную по названию из результатов. Из аргументов доступны только `offset` и `limit`. Без аргументов возвращается первая страница.

```json
{ "offset": 0, "limit": 20 }
```

Ответ содержит `items`, `total`, `offset`, `limit`. В каждой строке есть `schemaId`, `name`, `objectCount`, `revision`. Чтобы проверить состав, передайте выбранный ID в `wshcm_get_package_schema`. Для списков схем, состава схемы и просмотра ZIP размер страницы по умолчанию 100, допустимо 1–1000. Если сервер вернул `nextPage`, используйте его `tool` и `arguments`. При ограничении ответа в 256 KiB фактически выданная страница может быть короче запрошенной.

## wshcm_get_package_schema

Прочитать настройки схемы и страницу её объектов.

```json
{ "schemaId": "example", "limit": 50 }
```

Возвращает `name`, `schemaId`, `settings`, `objectCount`, `revision`, `objects`, `offset` и `limit`. У объекта есть `id`, `type`, `name`, `editable`. Возьмите `revision` для изменения состава или экспорта. Она относится к общему документу схем, поэтому правка соседней схемы может потребовать нового чтения.

## wshcm_save_package_schema

Создать именованную схему или поменять её имя, настройки и признаки редактируемости. Для создания достаточно имени. Здесь схема также будет включать определения полей заявок.

```json
{ "name": "Настройки заявок", "settings": { "processCustomTemplates": true, "customTemplates": ["request_type"] } }
```

Для изменения передайте `schemaId`, актуальную `revision` и нужные `name`, `settings` или `editable: [{id, editable}]`. В настройках также доступны `processAccessRoles` и `files` с элементами `{code,type,url,baseUrl?}`. Ответ включает `schemaId`, `revision`, `operation` и `errors`. Для пополнения и сокращения состава предназначены два следующих вызова.

## wshcm_add_package_objects

Добавить объекты в существующую схему. Обязательны `schemaId`, `revision` и непустой `objectIds`, до 10 000 ID.

```json
{ "schemaId": "example", "revision": "<revision>", "objectIds": ["9007199254740993"], "includeRelatedObjects": true }
```

Настройки включения `includeCategories`, `includeRelatedObjects`, `includeFiles` и `includeAssessmentItems` по умолчанию выключены. Связанные объекты выбирает штатная логика по типизированным ссылкам XMD. Например, шестнадцатеричные ID в `wvars` у веб-шаблонов и текстовый `mode`, указывающий на `web_mode`, могут потребовать явных ID. Проверьте `errors`, результат `operation` и состав через `wshcm_get_package_schema`. Для следующей правки используйте свежую `revision`.

## wshcm_remove_package_objects

Исключить перечисленные ID из состава, сохранив сами объекты в HCM.

```json
{ "schemaId": "example", "revision": "<revision>", "objectIds": ["9007199254740993"] }
```

Лимит — 10 000 ID. В ответе есть `schemaId`, новая `revision`, `operation` и `errors`. Сохранённый ранее ZIP содержит прежний состав. Для обновлённого архива выполните экспорт с текущей ревизией.

## wshcm_delete_package_schema

Удалить именованную схему целиком. Операция меняет реестр схем, объекты из состава остаются в HCM.

```json
{ "schemaId": "example", "revision": "<revision>" }
```

Сервер повторно сверяет снимок реестра перед записью. В ответе проверьте `schemaId`, `operation` и `errors`. При конфликте заново прочитайте реестр. При потере ответа проверьте ранее заданный `operationId`.

## wshcm_export_package

Собрать архив по точным ID, по типам определений или из сохранённой схемы. Прямой экспорт оставляет список схем и выбранный в админке пакет в прежнем состоянии.

```json
{ "objectIds": ["9007199254740993"], "customTemplates": ["request_type"], "operationId": "11111111-1111-4111-8111-111111111111" }
```

В прямом режиме передайте непустой `objectIds`, непустой `customTemplates` или оба списка. Доступны те же флаги включения, что при добавлении в схему. В режиме сохранённой схемы передайте `schemaId` с `revision`, а выбор типов задайте в её настройках. **В обоих режимах** выбор `request_type` означает все зарегистрированные шаблоны этого типа. Для переноса самих записей типов заявок включите их ID отдельно.

Без `outputPath` инструмент создаёт `~/.boristype/packages/export/<operationId>.zip` и возвращает его абсолютный `exportPath`. Для экспорта в корень проекта или существующую подпапку укажите имя нового ZIP. Например, следующий вызов создаёт `agents.zip` рядом с файлами проекта.

```json
{ "objectIds": ["9007199254740993"], "outputPath": "agents.zip" }
```

Для общей папки можно указать абсолютный путь, например `/srv/packages/export/agents.zip`. Каталог экспорта создаётся при первом экспорте в него. Пользовательские подпапки должны существовать. Для публикации готового файла каталог назначения должен поддерживать жёсткие ссылки (например, ext4 или NTFS). Существующий файл сохраняется, при совпадении имени выберите другое. `artifact` содержит отдельный служебный снимок, его `artifactId`, `localPath`, `sizeBytes`, `sha256`, `mimeType` и `expiresAt`. Настройка `--package-artifact-directory` управляет хранилищем снимков.

Проверьте `status`, `objects`, `missingCount`, `missingIds`, `customTemplateTypes`, `missingCustomTemplates` и `errors`. `verification: "archive_membership"` означает сверку с содержимым ZIP. При `partial` файл может существовать, хотя часть выбранного пропущена. В частности, на проверенной HCM 2025.2.1333 в архив мог не попасть тип, у которого настроены только общие страницы. Экспорт может создавать временные файлы и штатные отчёты на HCM.

## wshcm_inspect_package

Просмотреть ZIP **на целевом стенде**. Передайте один источник — `artifactId` из доступного хранилища снимков или `localPath`. Для ZIP в одном проекте путь симметричен экспорту.

```json
{ "localPath": "agents.zip", "limit": 20 }
```

| Где лежит ZIP на машине MCP                  | Как передать путь                                                                                                                   |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Общий каталог `~/.boristype/packages/import` | Положите сюда входной ZIP и передайте его абсолютный путь. Каталог можно создать при первом переносе.                               |
| Общий каталог `~/.boristype/packages/export` | Передайте `exportPath` из ответа экспорта напрямую. Оба процесса MCP должны видеть файл по этому пути.                              |
| Проект                                       | При одном корне подходят `agents.zip` и `release/agents.zip`. При нескольких корнях укажите абсолютный путь внутри нужного проекта. |

Каталоги обмена настраиваются независимо при запуске, например `--package-import-directory /srv/packages/import --package-export-directory /srv/packages/export`. На разных машинах понадобится общий том или перенос ZIP в доступный каталог целевого MCP. Обе папки предназначены для чтения пакетов, `export` также принимает результат экспорта.

Для пути в проекте MCP запрашивает у клиента локальные `file:`-корни через `roots/list`. Если клиент их не предоставляет, задайте `--project-directory /work/my-project`. Этот флаг имеет приоритет над списком клиента. `--project-directory .` выбирает рабочую папку, **из которой запущен процесс MCP**. Без флага домашняя папка целиком и корень диска автоматически не принимаются как проекты. Проект и каталог обмена должны быть доступны процессу MCP. Переход через `..`, ссылки внутри разрешённых каталогов и входные файлы с несколькими жёсткими ссылками отклоняются.

MCP проверяет свою копию архива. При ошибке формата удаляет её, сохраняя оригинал. При успехе уже этот вызов загружает архив на HCM для штатного предпросмотра. `ImportPathDenied` означает, что путь отклонён. Для ZIP, полученного от этого MCP через экспорт, передайте `artifactId` напрямую. Объекты целевого стенда применяются отдельным вызовом. Возвращаются `inspectionId`, `artifact`, `operation`, `items`, `offset`, `limit`, `total`. В строках пакета могут присутствовать `customTemplateTypes`. Следующую страницу запросите с `inspectionId` и новым `offset` либо через `nextPage`. Чтение страниц также требует доступности HCM. Лимиты ZIP — 128 MiB, 512 MiB в распакованном виде, до 10 000 записей, глубина вложенности архивов 2, XML до 32 MiB.

## wshcm_import_package

Применить просмотренный состав на целевом стенде. Обязателен `inspectionId` от inspect в том же экземпляре MCP. Этот пример включает определения полей и страниц.

```json
{ "inspectionId": "<inspectionId>", "includeCustomTemplates": true, "operationId": "22222222-2222-4222-8222-222222222222" }
```

**По умолчанию выбирается весь просмотренный снимок**, независимо от страниц, открытых клиентом. Для подмножества задайте `packageIds` или `objectIds` из этого снимка. Отдельные составляющие требуют явных флагов `includeCustomTemplates`, `includeAccessRoles`, `includeFiles`, `includeDeletions`, `includeLists`. По умолчанию также выключены `skipConflictingIds`, `allowVersionMismatch`, `allowReimport`. Перед применением проверяются целевая среда, целостность архива и конфликты. Поддерживаются типы пакетов `objects`, `courses`, `web`, `custom_file`. Для последнего назначение должно быть внутри `x-local://custom/`.

Ответ — запись операции с `operationId`, `status`, `phase`, `reportIds`, `downloadIds` и `verification`. Значение `completed` с `platform_report_only` подтверждает завершение штатной обработки. Для проверки конкретной записи прочитайте её по ID на целевой стороне, а для шаблона перечитайте определения. При потере ответа запросите состояние операции.

## wshcm_get_package_operation

Узнать, что сервер успел подтвердить, используя UUID, заданный **до** экспорта, предпросмотра, импорта или изменения схемы.

```json
{ "operationId": "22222222-2222-4222-8222-222222222222" }
```

Запросите запись на том же стенде под тем же аккаунтом. Возможные `status` — `running`, `completed`, `partial`, `failed`, `unknown`. Сопоставьте `phase`, `verification` и идентификаторы отчётов с ожидаемым действием. В экземпляре, выполнившем экспорт, запись содержит служебный `artifact` и при успешной записи файла — `exportPath`. Если после сборки HCM запись ZIP завершилась с `ExportWriteError`, запросите операцию по UUID, чтобы получить сохранённый снимок. При `ReceiptUnavailable` исход неизвестен. Таймаут клиента не останавливает обработку, а сбой следующего шага может оставить эффекты предыдущих. До повторного запуска проверьте состояние целевых объектов.
