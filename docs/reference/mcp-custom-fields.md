# Настраиваемые поля и страницы

В веб-админке эти определения открываются через нижнюю левую шестерёнку → **Настраиваемые поля**. Например, у подразделения можно настроить общие поля, а у заявок — отдельный набор полей и страниц для конкретного типа заявки. MCP разделяет чтение конфигурации, её изменение и заполнение карточки. Значение конкретной заявки лежит в XML её документа.

## wshcm_get_custom_field_definitions

Узнать, какие шаблоны зарегистрированы, или прочитать поля и страницы одной области. Выберите один из двух вариантов ввода.

| Задача                             | Аргументы                                                                    | Что взять из результата                                      |
| ---------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Найти шаблоны заявок               | `{"mode":"list","objectType":"request"}`                                     | `templateType`, `templateSelector`, `templates[].templateId` |
| Прочитать общие поля подразделения | `{"scope":{"objectType":"subdivision"}}`                                     | Определения и `revision` для правки этой области             |
| Прочитать один тип заявки          | `{"scope":{"objectType":"request_type","templateId":"6405466310999430311"}}` | Поля и страницы именно этого шаблона                         |

Пример входа для поиска шаблона по документу:

```json
{ "mode": "list", "objectType": "request", "offset": 0, "limit": 20 }
```

Для `request` ответ указывает `templateType: "request_type"` и `templateSelector: "request_type_id"`. Если вы работаете с конкретной заявкой, откройте её через `wshcm_get_object` и возьмите ID из поля, указанного селектором. Передайте его десятичной строкой и используйте возвращённый `templateType` в `scope.objectType`. Например, шестнадцатеричный ID из XML можно преобразовать в JS через `BigInt(hex).toString(10)`.

В режиме списка `common` содержит счётчики общей области или `null`, `templates` перечисляет зарегистрированные шаблоны с `templateId`, `fieldCount`, `pageCount` и доступным `title`. Пустые зарегистрированные шаблоны тоже видны. `offset` по умолчанию 0, `limit` — 50, максимум 100. `total` относится к реестру на момент запроса. Код раздела и селектор могут быть `null`. Само присутствие ID в списке ещё не подтверждает существование владельца.

Чтение по `scope` возвращает `exists`, `scope`, `fields`, `pages`, список допустимых типов `fieldTypes` и `revision`. Поля и страницы следуют в порядке HCM. Для существующего владельца без конфигурации возвращаются `exists: false` и пустые списки. Эту область можно наполнить через patch. Ревизию выдаёт именно чтение по `scope`.

## wshcm_patch_custom_field_definitions

Добавить, изменить, переместить или удалить определения в одной области. Передайте прежний `scope`, его `revision` из текущего экземпляра MCP и от 1 до 100 упорядоченных `operations`. Замените в примере ID на ID своего типа заявки, а `<revision>` на результат чтения. Сначала создаётся страница, поэтому следующее действие уже может сослаться на неё.

```json
{
  "scope": { "objectType": "request_type", "templateId": "6405466310999430311" },
  "revision": "<revision>",
  "dryRun": true,
  "operations": [
    { "op": "upsertPage", "id": "delivery", "set": { "title": "Получение" } },
    {
      "op": "upsertField",
      "name": "delivery_method",
      "set": { "title": "Способ получения", "type": "combo", "options": ["Самовывоз", "Доставка"], "pageId": "delivery" }
    }
  ]
}
```

| Действие                    | Аргументы и эффект                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `upsertField`, `upsertPage` | `name` поля или `id` страницы и объект `set`. Новый элемент добавляется в конец, существующий меняется на месте. Пропущенные свойства сохраняются.      |
| `moveField`, `movePage`     | Ключ перемещаемого элемента и ровно один ключ соседа в `before` или `after`.                                                                            |
| `renameField`               | Старый ключ в `name`, новый в `newName`. Зависимые условия и значения документов мигрируются отдельно.                                                  |
| `removeField`, `removePage` | Ключ удаляемого элемента. Перед удалением страницы снимите привязки полей через `pageId: null` либо переместите поля. Это можно сделать в той же пачке. |
| `removeTemplate`            | Удаляет определения полей и страниц всего шаблона, выбранного по `scope.templateId`. Запись владельца и значения в документах сохраняются.              |

У поля можно менять `title`, `type`, `required`, `showOnPortal`, `pageId`. Варианты `combo` и `list` передаются массивом строк в `options`, ссылки `foreign_elem` задаются через `catalog` и `catalogFilter`. Расширенные настройки — `comment`, `defaultValueFormula`, `validationCondition`, `width`, `height`, `visualClass`, `maxChars`. Формулы, условия, размеры и фильтр сохраняются текстом. Для очистки расширенных текстовых настроек используйте `null`.

`visibilityConditions` заменяет весь упорядоченный список правил. Например, `[{"field":"status_id","type":"string","operator":"eq","value":"active"}]`. Для настраиваемого поля добавьте `isCustomField: true`. Допустимы коды `eq`, `neq`, `gt`, `lt`, `gte`, `lte`, `cn`, `ncn`, соединения `join` (`and` или `or`) и парные `bracket`. Пустой массив очищает условия или варианты выбора.

У страницы доступны `title`, код роли `accessRole` и точная десятичная строка `accessGroupId`. Если заданы оба ограничения, обычному пользователю нужны оба совпадения. `null` снимает соответствующее ограничение. Правка ограничений и удаление защищённой страницы либо шаблона с такой страницей требуют роли HCM `admin`.

В ответе проверьте `changed`, `dryRun`, `writeStatus`, итоговые поля и страницы. Предпросмотр и отсутствие изменений дают `not_attempted`. Для применения отправьте операции с `dryRun: false`. После сохранения используйте возвращённую ревизию. Изменение **любой** области общего реестра может вызвать конфликт. При конфликте или неизвестном исходе перечитайте тот же `scope`. Ошибка `CacheMismatch` означает расхождение сохранённого реестра и кэша HCM.

### Как заполнить поле в одной заявке

После сохранения определения откройте нужную заявку через [чтение документа](./mcp-objects#wshcm-get-object). Для поля из примера частичный XML имеет вид:

```xml
<request>
  <custom_elems>
    <custom_elem><name>delivery_method</name><value>Доставка</value></custom_elem>
  </custom_elems>
</request>
```

Передайте его в [частичную правку документа](./mcp-objects#wshcm-patch-object) с ID **заявки** и её `readToken`. Для переноса самих определений на другой стенд выберите `request_type` в [экспорте пакета](./mcp-packages#wshcm-export-package). Такой выбор включает все настроенные шаблоны этого типа.

### Как использовать такое же поле в другом типе заявки

Прочитайте исходный и целевой шаблоны через `scope`. Возьмите у исходного поля ключ, тип, варианты и нужные настройки. Проверьте в целевом шаблоне страницу и поля, на которые ссылаются условия видимости. Если страницы ещё нет, добавьте `upsertPage` перед `upsertField`. Выполните patch с **ревизией целевого шаблона** и проверьте `fields` и `pages` в предпросмотре. При совпадении ключа `upsertField` изменит уже существующее определение. Получившиеся определения затем можно менять независимо.
