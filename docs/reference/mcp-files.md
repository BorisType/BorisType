# Файлы и каталоги HCM

Девять файловых инструментов работают с физическими файлами **на сервере HCM**. Передавайте полный URL `x-local://`. Если приложение читает тот же URL через `LoadUrlData`, источником может быть SQL-хранилище `spxml_blobs`. Хеш, поиск и правка относятся к дисковой копии. При первом обращении SDK подготавливает файловую DLL. [Диагностика runtime](./mcp-execution#wshcm-runtime-status)

## wshcm_list_directory

Посмотреть один уровень известного каталога. Единственный аргумент — `path`.

```json
{ "path": "x-local://wt/web/" }
```

Текст ответа содержит JSON-массив с `name` и `isDirectory`, отсортированный по имени (ordinal). У ссылок есть `isSymbolicLink: true`. Сервер отказывает при попытке открыть ссылку как корневой каталог. При более чем 10 000 элементах возвращает ошибку. Для отбора по имени во вложенных каталогах используйте поиск.

## wshcm_search_files

Найти файл по имени или строке в содержимом. Обязателен каталог `path`. Для поиска по имени достаточно `pattern`. Добавьте `query`, чтобы читать совпадающие файлы построчно.

```json
{
  "path": "x-local://wt/web/",
  "pattern": "**/*.bs",
  "excludePatterns": ["vendor/**"],
  "query": "tools.get_version",
  "maxResults": 20
}
```

Имена учитывают регистр. Glob принимает `*`, `?` и целый сегмент `**`. Шаблон без `/` проверяется по имени файла на любой глубине. `excludePatterns` принимает до 32 шаблонов. По содержимому поиск по умолчанию буквальный. `ignoreCase` меняет сравнение содержимого, `regex: true` включает построчный .NET regex с лимитом 50 мс на сопоставление.

| Параметр                              | По умолчанию | Максимум |
| ------------------------------------- | -----------: | -------: |
| `maxResults`                          |          200 |    1 000 |
| `maxEntries`                          |       10 000 |  100 000 |
| `maxDepth` (файлы корня на глубине 0) |           10 |       32 |
| `maxFileBytes`                        |        1 MiB |    8 MiB |
| `maxTotalBytes`                       |       16 MiB |   64 MiB |
| `maxLineLength` (единицы UTF-16)      |        2 000 |    8 192 |
| `timeoutMs`                           |        2 000 |   10 000 |

В ответе `matches[].path` задаётся относительно `root`, с разделителем `/`. При поиске содержимого возвращаются `line`, `column` (с 1, колонка в UTF-16) и текст строки. На строку приходится до одного совпадения. Для правки соберите URL из корня и пути и вызовите `wshcm_read_file`.

Проверяйте `stats`, все счётчики `skipped` и `limitReason`, даже при пустом `matches`. Например, `skipped.invalidEncoding` учитывает файлы с неподдерживаемой кодировкой, `skipped.longLines` — пропущенные строки. Значение `"output"` указывает на предел выдачи в 256 KiB. При неполном охвате сузьте каталог или шаблон и повторите поиск.

## wshcm_get_file_info

Узнать размер, время изменения или вид записи перед выбором способа работы. Принимает `path`, в том числе для бинарных и крупных файлов.

```json
{ "path": "x-local://wt/web/app.bs" }
```

Ответ содержит `name`, `isDirectory`, `modifiedUtc` и, для файла, `sizeBytes`. Для получения текста и права правки требуется отдельный вызов чтения. Ссылки и junction отклоняются.

## wshcm_read_file

Прочитать весь текст или включительный диапазон строк и получить токен для следующей правки.

```json
{ "path": "x-local://wt/web/app.bs", "startLine": 10, "endLine": 30 }
```

Строки нумеруются с 1. Без границ читается весь файл. Конец за пределами файла обрезается, начало за пределами даёт ошибку. Для обоих режимов весь файл должен помещаться в 1 MiB и содержать корректный UTF-8 без NUL.

В ответе `content` сохраняет переводы строк, `bom` сообщает о снятом начальном BOM, `sha256` вычислен от исходных байтов. `startLine/endLine/totalLines` описывают строки, `startOffset/endOffset/totalLength` — позиции UTF-16 без BOM, правая граница смещения исключительная. Передайте выданный `readToken` при чтении следующего диапазона того же URL, чтобы накопить покрытие одной версии. Для правки берите последний токен. Новое чтение без токена начинает покрытие заново. Срок хранения — 30 минут с последнего чтения, до 128 файлов и 256 объединённых диапазонов на файл в экземпляре MCP.

## wshcm_edit_file

Изменить прочитанный фрагмент. Скопируйте `oldText` из `content`, включая значимые пробелы и переводы строк. Подставьте последний токен чтения этого URL.

```json
{
  "path": "x-local://wt/web/app.bs",
  "readToken": "<readToken>",
  "edits": [{ "oldText": "var limit = 10;", "newText": "var limit = 20;" }],
  "dryRun": true
}
```

До 100 замен проверяются последовательно в памяти. Каждый непустой `oldText` должен встречаться ровно один раз в промежуточном тексте и целиком входить в прочитанный диапазон. Неоднозначность или ошибка следующей замены останавливает запись всего набора. Дополнительный `expectedSha256` сверяется с хешем чтения.

В ответе есть `status`, `previousSha256`, `sha256` и `editsCount`. При `dry_run` выдаётся также полный кандидат в `content`. Предпросмотр сохраняет токен и прежнее покрытие. Чтобы применить показанные замены, повторите аргументы с `dryRun: false`. Возможны `applied` и `unchanged`. После попытки применения перечитайте файл. При `Conflict` изменились исходные байты, при `ReadRequired` нужно заново прочитать нужный диапазон. Между последней сверкой байтов и записью возможна внешняя правка.

## wshcm_write_file

Создать новый файл с точным содержимым. Родительский каталог должен существовать. Режим по умолчанию `create` отклоняет занятое имя.

```json
{ "path": "x-local://custom/example/message.txt", "content": "Готово\n" }
```

Для полной перезаписи передайте `mode: "overwrite"` и `readToken` с покрытием всего текущего файла. Запись формирует UTF-8 с BOM, максимум 1 MiB вместе с BOM. Успех возвращается текстом `File written: <path>`. Новое чтение даёт фактические байты и свежий токен. Для замены небольшого фрагмента с сохранением исходного BOM используйте `wshcm_edit_file`.

## wshcm_create_directory

Подготовить каталог, в том числе родителей для `wshcm_write_file`.

```json
{ "path": "x-local://custom/example/" }
```

`created: true` означает создание каталога, `false` — он уже существовал. Файл на месте каталога или ссылка в пути дают ошибку. Если один из шагов создания цепочки завершился ошибкой, уже созданные родители могут сохраниться.

## wshcm_move_file

Переместить или переименовать один файл, включая бинарный. Оба URL относятся к файловой системе HCM.

```json
{ "source": "x-local://custom/example/message.txt", "destination": "x-local://custom/example/archive.txt" }
```

Успех возвращает `moved: true`. Нужны существующий родитель назначения и свободное имя. Между файловыми системами возможна ошибка `CrossDevice`. Каталоги, ссылки и источник с атрибутом read-only отклоняются. Текстовое чтение перед перемещением необязательно. После попытки токены обоих URL теряют силу.

## wshcm_delete_file

Удалить один существующий физический файл. Достаточно его URL.

```json
{ "path": "x-local://custom/example/archive.txt" }
```

Успех возвращается текстом `File deleted: <path>`. Отсутствующий файл, каталог, ссылка или файл с атрибутом read-only дают ошибку. Попытка удаления сбрасывает токен URL. Для документа HCM предусмотрено отдельное [перемещение в корзину](./mcp-objects#wshcm-delete-object).
