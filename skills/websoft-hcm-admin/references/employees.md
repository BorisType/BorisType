# Сотрудники: поиск и проверка карточки

## Источники и область применимости

**Наблюдение браузера, 2026-11-10:** WebSoft HCM 2025.2.1333,
Linux x64, C-runtime/.NET 9.0.11, PostgreSQL 16, legacy model,
русский веб-администратор. Проверялась карточка вымышленного сотрудника,
предварительно созданного через XML API: каталог, открытие, разделы и значения
полей. Браузерные создание, изменение, сохранение и удаление не проверялись.
На Windows, новой модели и других версиях этот маршрут не проверен.

**Пояснение пользователя, 2026-11-10:** полнотекстовая переиндексация выполняется
по расписанию, например каждые 20 минут; обычные фильтры работают сразу,
без ожидания полнотекстового индекса. Конкретный период зависит от установки.
Само расписание и последующее появление записи после переиндексации в этой
проверке не измерялись. Точная последовательность настройки обычного фильтра
пока не проверена; ниже для него указан только общий способ действий.

## Открыть каталог и найти запись

1. Открой `/admin` на нужном сервере с доступом к веб-администратору.
   На проверенной установке произошёл переход на `/spxml_web/main.htm`.
2. Перейди в **Персонал → Сотрудники**.
3. Для обычного текстового поиска введи значение в строку над каталогом
   и нажми **Enter**. В проверке ввод полного ФИО и фамилии нового сотрудника
   вернул пустую выдачу, хотя запись уже существовала в каталоге и XML API.
4. Для свежей записи очисти строку и нажми **Enter**, затем используй обычный
   **Фильтр** по доступному полю с известным значением либо найди строку
   в каталоге. Условия и поля фильтра уточняй по текущему интерфейсу;
   логин, код и ID не обещаны как доступные поля любого фильтра.
   Проверь также оставшиеся условия, область списка и страницы выдачи.
5. Сопоставь найденную запись с ожидаемыми данными. ФИО может совпадать у разных
   людей; для идентификации используй также известные логин, код или почту,
   если они доступны. Не создавай дубль из-за пустого полнотекстового поиска.
6. Открой строку сотрудника **двойным щелчком по ФИО**. В проверке карточка
   открылась внутри той же страницы; новую вкладку браузера ожидать не нужно.

## Проверить поля

| Раздел карточки     | Поля                               | Что сверять                                                                                               |
| ------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Общие сведения**  | **Фамилия**, **Имя**, **Отчество** | Каждое значение отдельно, а не только собранное ФИО в заголовке                                           |
| **Общие сведения**  | **Логин**, **Код**                 | Идентификацию нужной записи, если значения известны                                                       |
| **Общие сведения**  | **Пароль**                         | На проверенном стенде виден открытым текстом; видимое значение само по себе не подтверждает успешный вход |
| **Анкетные данные** | **Телефон**, **E-mail**            | Телефон и адрес электронной почты из исходных данных; не путать с мобильным телефоном и внутренним e-mail |

Для созданной через XML API записи полезно сопоставить значения карточки
с полями `lastname`, `firstname`, `middlename`, `login`, `code`, `phone`, `email`
корня `collaborator`. Вычисляемое `fullname` не заменяет отдельные поля ФИО.
Доступ к XML API для самого браузерного сценария не требуется.

После открытия нужного раздела дождись загрузки и получи свежий snapshot.
Для проверки отображения не нужно менять поля или нажимать сохранение.

## Снимки и результат

Снимай общий раздел и контактные данные отдельно, если они не помещаются вместе.
Сохраняй в кадре заголовок карточки или другой признак нужной записи, подписи
проверяемых полей и их значения. Проверяй исходный снимок перед передачей:
пароль, токены и чужие персональные данные исключай или закрывай на изображении.
Исходные снимки с секретами не добавляй в распространяемый skill.

В результате перечисли фактически сверенные поля и оставшиеся расхождения.
Открытие карточки после XML-сохранения подтверждает отображение данных из этого
пути записи. Для проверки сохранения через UI нужен отдельный сценарий:
разрешённое изменение тестового объекта, сохранение, повторное открытие и сверка.
