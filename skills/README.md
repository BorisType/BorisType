# Agent skills

Переносимые skills хранятся в этом репозитории и устанавливаются независимо
через `npx skills add`. Каталог может содержать и знания WebSoft HCM,
и отдельные инструкции для инструментов BorisType. Каждый skill имеет
собственную область применения и устанавливается по выбору пользователя.

| Skill                                           | Содержание                                                                                                                                        |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| [websoft-hcm](websoft-hcm/SKILL.md)             | Платформа: URL, ini, SQL blobs, числа, StrSignedInt, точные ID и SQL→XML. Источники и ограниченные probes; независим от компилятора и нашего MCP. |
| [boristype-mcp](boristype-mcp/SKILL.md)         | Работа с файловыми tools и XQuery/SQL: readToken, диапазоны, SQL→XML, точные ID, усечение и неизвестный исход выполнения.                         |
| [websoft-hcm-admin](websoft-hcm-admin/SKILL.md) | Веб-администратор: поиск сотрудника, карточка и контакты, полнотекстовый индекс и обычные фильтры, снимки без паролей.                            |

Установка и выбор: [руководство](../docs/guides/agent-skills.md).

## Как пополнять знания

Добавляй факт в reference соответствующего skill. Entry point оставляй коротким:
когда применять сведения, какие ограничения учитывать и какой reference читать.
Самостоятельную тему выделяй в соседний skill, когда для неё готов полезный материал.

У каждого технического правила должны быть:

- Наблюдаемое поведение и условия: версия, ОС, runtime, место выполнения.
- Источник: конкретная статья, declarations с revision/файлом, код поставки
  или воспроизводимая проба. Эти виды evidence различаются явно.
- Actual/expected и минимальный способ воспроизведения, если была проба.
- Известные расхождения и непроверенные предположения.

Короткая запись может выглядеть так:

> **Наблюдение C-runtime:** Linux HCM 2025.2.1333, eval во временной библиотеке.
> `UrlToFilePath("x-app://wt/web/space%20name.txt")` сохранил `%20` буквально.
> Для `file:` в той же среде `%20` декодирован в пробел. Windows не проверена.

Сохраняй существенные результаты исследований в устанавливаемых references.
`plans/` может хранить историю работ и проверки, но установленный skill должен
быть полезен без checkout репозитория. Локальные ссылки внутри skill направляй
на его собственные файлы; другой skill может быть не установлен.

Vendor-код, приватные конфиги, credentials и локальные пути к стендам остаются
вне распространяемого skill. Подключение к документации или стенду описывай
как доступную возможность, а не обязательную зависимость от нашего окружения.

Перед публикацией проверь discovery, выборочную установку вместе с references,
внутренние ссылки и применение на конкретных вопросах в отдельном контексте.
Первая проверка: [план и результаты](../plans/skills/01-websoft-hcm.md).
