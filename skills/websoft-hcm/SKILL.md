# WebSoft HCM

Применяй сведения о платформе с учётом версии, ОС и места выполнения.
Справочники покрывают пути, конфигурацию, маршрутизацию URL в хранилища,
числовое форматирование и SQL→XML.

## Выбор сведений

Для `x-local`, `x-app`, `file`, `UrlToFilePath`, ошибок `Url host is not allowed`
и настроек `.ini` прочитай [пути и конфигурацию](references/paths-and-configuration.md).
Там же доступны ограниченные probes и условия их выполнения.
Для операций с файлами, `LoadUrlData`, `PutUrlData`, `DeleteUrl`, `DB-STORE-HOOK`
и `spxml_blobs` прочитай [URL storage и blobs](references/url-storage-and-blobs.md).
Другие темы исследуй по доступным источникам; справочник постепенно пополняется.

Для отрицательных чисел, `StrInt`/`StrSignedInt`/`StrReal`, точных больших ID
и потерь SQL→XML прочитай [числа и SQL mapping](references/numbers-and-sql.md).
Там различаются формат вывода, арифметика, JSON и значение XML-поля до SOAP;
есть проверенные результаты и самостоятельные ограниченные probes.

## Операции с файлами

Перед чтением, поиском или редактированием различай физический файл и логический
ресурс URL. `UrlToFilePath` возвращает путь, но не устанавливает хранилище URL API.
На проверенном Linux C-runtime HCM 2025.2.1333 для `x-local://wt_data/` с SQL hook:

- `LoadUrlData` читал blob, даже когда на диске лежало другое содержимое.
- При отсутствии blob URL-чтение импортировало дисковый файл в БД.
- `DeleteUrl` удалял blob, оставляя файл; последующее чтение снова создавало blob.

Выбирай чтение и запись для нужного хранилища, а результат правки проверяй тем
способом, которым ресурс читает целевой код. Поиск по диску не покрывает SQL blobs.
Совпадение физических путей не обосновывает замену `x-local` на `x-app` или `file`.
Для другой конфигурации эти наблюдения требуют проверки; само наличие `DATA-DB`
не доказывает SQL routing. Источники, конфигурация и пробы — в справочнике выше.

## Проверка применимости

Установи версию HCM, ОС, реализацию runtime и место исполнения: сервер,
WebTutorAdmin, UI, агент или библиотека/eval. Если этих данных нет, обозначь
границы ответа и продолжай доступное исследование.

Различай документацию, TypeScript declarations, код поставки, JS/mock и
наблюдение C-runtime. Пример Windows или результат JS не подтверждает Linux/C.
Проверяй, что сведения относятся к нужной операции: преобразование URL
не доказывает существование ресурса или возможность доступа через обычную ФС.

Datex может пропускать аргументы и ошибаться. Для документации используй
`wshcm-docs`, когда он доступен, либо доступные страницы документации.
Сопоставляй сигнатуры с [wshcmx/types](https://github.com/wshcmx/types), фиксируя
revision и файл. Declarations не доказывают runtime semantics; отсутствие
declaration не доказывает отсутствие API.

## Новые наблюдения

Описывай правило через наблюдаемое поведение, область применимости и источник.
Для пробы сохраняй минимальный исходник, actual/expected, версию/ОС/runtime,
carrier и результат очистки. Статические находки и гипотезы отмечай явно.

Пробы выполняй на доступном тестовом стенде в пределах задачи, с конечными
циклами и проверкой очистки. Timeout клиента не отменяет серверный код;
при timeout сначала выясни, продолжается ли предыдущий вызов.

Публикуемые материалы должны воспроизводить знание без локальных абсолютных
путей к инструментам, учётных данных и полного копирования vendor-кода.
