# XMD: схема, объект, каталог и хранение

## Объектная модель и её два поколения

Полный объект HCM имеет XML-представление. XMD задаёт доступную структуру,
типы и поведение; открытый `XmlDocument` связывает данные с формой, URL и
операциями жизненного цикла. `TopElem` — корень данных, `Form.TopElem` — корень
описания структуры. Ссылка на поле — `XmlElem`, а не просто JS primitive.

Каталог — доступное для запросов представление данных. В legacy-модели он
описывается и регистрируется отдельно от полного объекта. SQL-провайдер хранит
каталожные строки отдельно от полного XML. Состав и количество каталогов не
обязаны совпадать с типами документов.

В документации новой модели каталог назван автоматически создаваемым списком
объектов типа, с pluralization имени и исключениями `DOC-ONLY`. Это **другой
контракт**, который нельзя автоматически переносить на legacy HCM.

Источники:
[объекты](https://wshcm-docs.boristype.dev/news/platform/7117695600308124380.html),
[каталоги](https://wshcm-docs.boristype.dev/news/platform/7117695531631503784.html),
[старая и новая модели](https://wshcm-docs.boristype.dev/datex/common/5665465792879477188.html).
На исследованном C-стенде `DefaultDb.UseObjectTypes=false`,
`ObjectForms` пуст; `GetOptObjectForm` не найден, `GetObjectFormUrl` завершился
ошибкой. Указанная в declarations новая модель пока не является рабочим
универсальным discovery для этого сервера.

## Что находится в XMD

| Конструкция                                        | Назначение / ограничения                                                                   |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `SPXML-FORM`                                       | Контейнер формы; это ещё не экземпляр данных                                               |
| Корневой тег объекта                               | Имя структуры, например `cost_center`; не выводить его только из имени файла               |
| `USE FORM`                                         | Загрузка другой формы и общих определений; относительные URL требуют контекста             |
| `SAMPLE="1"`                                       | Переиспользуемое описание, а не отдельная запись БД                                        |
| `INHERIT TYPE`                                     | Вставляет поля/методы на текущем уровне структуры                                          |
| Поле с `TYPE="..._base"`                           | Создаёт вложенную структуру указанного типа; отличается от `INHERIT`                       |
| `TYPE="string/integer/real/bool/date/variant/..."` | Тип данных; произвольное имя может обозначать составной тип                                |
| `MULTIPLE="1"`                                     | Повторяемый элемент; бывает составным или скалярным                                        |
| `PRIMARY-KEY`                                      | Ключ для поиска/сопоставления элементов; native `AddChild` допустил два одинаковых ключа   |
| `DEFAULT`, `EXPR-INIT`                             | Default и вычисляемая инициализация; не равнозначны правилам валидации                     |
| `NOT-NULL`, `NULL-FALSE`                           | Участвуют в представлении значений; не считать универсальным required validator            |
| `PROPERTY="1"`, `EXPR`, `PARAM`                    | Вычисляемое свойство/метод с исполняемым BS; не обычное сохраняемое поле                   |
| `TEMP="1"`                                         | Временные данные; native файл их не сохранил                                               |
| `SECONDARY`                                        | По declarations — вычисляемые вторичные данные; фактическая логика зависит от типа         |
| `FOREIGN-ARRAY`                                    | Выражение источника ссылок: каталог БД, статический справочник или иной массив             |
| `INDEXED`                                          | Инструкция каталогу/provider-у; фактическое наличие SQL-индекса требует отдельной проверки |
| `TITLE`, `TITLE-EXPR`, `DISP-NAME`                 | Метаданные отображения, могут использовать локализацию/выражения                           |
| `HIER`, `PARENT-ID-ELEM`                           | Метаданные иерархии; не доказательство защиты от циклов                                    |
| `STORE-SECTION`, `TIME`, `PRECISION`               | Дополнительные правила текста/дат/чисел; не терять при описании схемы                      |

Сведения об `INHERIT` и составном `TYPE` подтверждаются документацией и vendor
источниками; defaults, типы, foreign metadata и TEMP проверены выборочными
native-пробами. Остальные строки не являются полной спецификацией всех флагов.
Например, `STRICT` встречается в component XML и declarations; универсальный
набор его ограничений здесь не аттестован.

Документация:
[XMD](https://wshcm-docs.boristype.dev/news/platform/7117696163946095988.html),
[XMD объекта](https://wshcm-docs.boristype.dev/news/monolith/6680850105423121059.html),
[XMD каталога](https://wshcm-docs.boristype.dev/news/monolith/6680850926357737793.html).

## Это XML-подобный формат с расширениями SPXML

В выборке верхнего уровня `/WebsoftServer/wtv/` найдено **919 XMD и 609 XMS**.
Python `xml.etree.ElementTree` разобрал 848 XMD и отверг 71. Причины включают
повторяющиеся атрибуты `PARAM`, неэкранированные операторы в выражениях и
несвязанный namespace prefix. Например, повторяемый `PARAM` в методе является
частью используемой платформой нотации, хотя запрещён обычным XML parser.

Среди успешно разобранных файлов 434 имеют `CATALOG="1"`; это **нижняя оценка
для данной выборки**, а не полный реестр сервера. Компоненты, QTI, custom-типы
и вложенные каталоги этой инвентаризацией не покрыты. Ошибка strict parser не
означает, что форма ошибочна для SPXML. `FetchForm` исследованного сервера
успешно загрузил `wtv_cost_center.xmd` с `USE` на `wtv_general.xmd`, который
strict parser отвергает.

Следствие: Node/.NET parser полезен для ограниченного статического анализа,
но не заменяет платформенную загрузку зависимостей, наследования и расширений.
Нельзя автоматически исправлять vendor формы под обычный XML или считать
результат такого преобразования эквивалентным исходнику.

## Каталожная проекция и производные каталоги

Обычная legacy-пара:

```text
полный cost_center
  id, code, name, is_active, parent_id,
  subdivisions[], func_managers[], custom_elems[], comment, doc_info
             │ OnBuild
             ▼
каталожная строка cost_centers
  id, code, name, is_active, parent_id,
  поля доступа, modification_date, app_instance_id
```

`wtv_cost_centers.xmd` задаёт `CATALOG="1"`, `OBJECT-NAME="cost_center"`,
повторяемый `cost_center` с ключом `id` и `OnBuild`. Hook копирует одноимённые
поля через `AssignElem`, отдельно переносит даты и app instance из `doc_info`.
Native создание собственного объекта подтвердило обновление проекции и
отсутствие `comment` в каталоге при наличии его в полном документе.

Другой случай — `wtv_group_collaborators.xmd`: `MatchDocTypeExt`,
`OnBuildExt`, `OnDeleteExt`, `x-linked-catalogs="groups"`. При сохранении
группы код удаляет предыдущие строки по `group_id` и создаёт строки для
участников/позиций. Их `id` создаётся отдельно, `group_id` указывает на документ
группы. Поэтому `OpenDoc(UrlFromDocID(row.id))` **не является универсальным
переходом от каталога к объекту**. Проверены исходники; native группы не менялись.

Выделять нужно как минимум основной каталог объекта, каталог-связку,
статический справочник (`common.*`/`lists.*`) и динамический результат SQL/XQuery.
Наличие строки с `id` не доказывает, что она описывает отдельный объект.

Документация по проектированию:
[каталоги и каталоги-связки](https://wshcm-docs.boristype.dev/news/platform/7181344927844891439.html).
Дополнительные конкретные примеры — в [XMS-аудите](xms-and-business-logic.md).

## Значения, отсутствие и XML

На C-стенде:

- Пустой string имеет `Value=""`, `HasValue=false`; пустой integer —
  `Value=null`, `HasValue=false`. Эти состояния нельзя описывать только через JSON
  `null` либо `""` без метаданных типа и наличия значения.
- `DEFAULT="7"` создаёт значение. `Clear()` удаляет его в памяти;
  сохранение и повторное открытие снова применяют default 7.
- `NULL-FALSE="1" DEFAULT="false"` в собственной форме даёт `Value=false`,
  `HasValue=false`; `is_active DEFAULT=true NOT-NULL=1` — `HasValue=true`.
- Присваивание `"42"` integer-полю преобразуется в 42; `"not-an-integer"`
  завершается ошибкой. Это платформенное приведение, не повод принимать любые
  строки на входе MCP.
- Дубликаты `PRIMARY-KEY` в XML-массиве допустились при `AddChild` и сохранении
  собственного файла. Селектор только по ключу при дубликатах неоднозначен.
- `LoadData` с `<probe><n>9</n></probe>` изменил n и сохранил остальные поля:
  это merge, а не полная замена. `SetXml` из declarations на стенде недоступен.
- Неизвестный для заданной формы XML-тег не попал в открытый документ.
- `PROPERTY` может вычислять значение; сохраняемый XML его не содержит.
  TEMP также пропускается. Полный dump всех свойств объекта не равен XML-экспорту.

ID и целые передавать без JS Number: например, строка
`"9007199254740993"` сохранилась в foreign integer без потери единицы.
Дополнительная особенность: XML-сериализация тестового -78 дала
`18446744073709551538`, а повторное открытие восстановило -78. Это наблюдение
этой реализации, не переносимая XML/JSON-нотация signed integer.
См. также [известные числовые особенности](../../../skills/websoft-hcm/references/numbers-and-sql.md).

## Полная и сокращённая форма

`OpenDoc(url, 'form=...')` может открыть только часть данных. Удобно для чтения
больших документов и проверки доступа, но такая копия непригодна для общего
patch-save: native сохранение собственной сокращённой формы удалило массив и
прочие отсутствующие в ней поля, а также записало ссылку на сокращённую форму.

Нельзя обещать побайтовый lossless round-trip даже полной формы: неизвестные
поля, TEMP, PROPERTY, defaults, канонизация и schema drift меняют представление.
Raw storage XML, открытый XML по XMD и типизированный view для агента — разные
артефакты. Tool должен ясно обозначать, какой из них возвращается.

Источник:
[полная и упрощённая формы](https://wshcm-docs.boristype.dev/news/platform/7117695776200708693.html).

## Связи и custom fields

`FOREIGN-ARRAY` у `parent_id` возвращает `cost_centers` в reflection. Native
сохранение приняло ID отсутствующего объекта, а `OptForeignElem` вернул
`undefined`. Значит, эта декларация не гарантирует ссылочную целостность при
таком способе сохранения. `FOREIGN-ARRAY="common.*"` может ссылаться на
строковый справочник, а не на ID объектного документа.

Не обходить foreign-ссылки автоматически при выдаче документа: это меняет
стоимость, может открыть закрытые/чувствительные данные и создать циклический
граф. Возвращать саму ссылку; разрешение ссылок — отдельная явно ограниченная
операция.

В `wtv_general.xmd:2853` `custom_elems_base` задаёт
`custom_elems/custom_elem[name,value]`, где `value` — string. Метод
`check_fields_default_value` запрашивает шаблон через `tools.get_custom_template`
и может вычислять `default_value_eval`. Следовательно, «кастомное поле» может
иметь тип/required/default/проверки вне самой XMD. Описать его только как
string-массив недостаточно. Прикладной шаблон и server settings требуют
отдельного исследования и version fingerprint. Пользовательские типы `cc_*`
с генерируемыми XMD — ещё один механизм, отличный от custom_elems.

## Discovery без предположений о путях

На этом сервере работают `FindOptCatalog('cost_centers').Form.Url`,
`FetchForm(fullUrl)` и reflection элементов. Доступный
`common.exchange_object_types` содержит 414 записей; это прикладной список,
его полнота относительно всех registered catalogs не доказана.

`tools.get_object_form_url` в данной поставке (`wtv_tools.xml:8426`) строит
адреса по правилам qti / `cc_*` / wtv. Это полезный legacy helper,
но не общий resolver для namespaced component catalogs. Документация новых
компонентов использует полные пути и qualified names, например
`websoft.platform.security.user_settings`.

Для будущего schema tool нужны определение модели/возможностей, явный полный
URL формы или доказанное соответствие реестра, базовый URL для `USE`, раздельные
object/catalog identities, provenance и fingerprint фактически загруженной
схемы с её зависимостями. Один hash исходного XMD не обнаружит изменение
унаследованного base-типа или прикладного шаблона.

Источник:
[компонентные настройки и namespace](https://wshcm-docs.boristype.dev/news/platform/7297474251252561348.html).
Не переносить приведённую там актуальную компонентную архитектуру на старый
stand без проверки установленного компонента.

## SQL storage и файловая система

По документации мост хранит полные документы в object tables, метаданные/формы
в `spxml_objects`, каталоги — отдельно, binary — в `spxml_blobs`, сведения о
каталогах и ссылках — в metadata/foreign-array tables. Физическое расположение
и транзакции определяет provider; структура SQL не заменяет контракт XML API.

Raw SQL UPDATE каталога не является сохранением полного объекта. Правка XML
object table не доказывает перестроения всех проекций, hooks, кэшей или индекса.
Операции physical file tools не заменяют `OpenDoc`/`Save` для объектов и
логических URL, которые provider может хранить в БД.

Источники:
[архитектура SPXML→SQL](https://wshcm-docs.boristype.dev/news/platform/7119439504986790928.html),
[файлы и SQL blobs](../../../skills/websoft-hcm/references/url-storage-and-blobs.md).
Имена SQL-таблиц здесь — сведения источника, не инструкция писать их напрямую.
